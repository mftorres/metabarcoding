From raw Nanopore reads to taxonomic tables and a phylogenetic tree. Follow one step at a time, using the menu to return to the process you need.

This is an offline handbook. Double-click this HTML file in Windows to open it in Edge, Firefox or Chrome. No server, build, account or internet connection is needed to read it. Installation, external reference downloads and linked websites need internet.

Computer setup

1 · Enable Linux in Windows 11

WSL is the Windows Subsystem for Linux. It lets you run Ubuntu and this pipeline alongside Windows. These instructions target an Intel/AMD Windows 11 computer (Linux x86_64).

  1. Open Start, search for PowerShell, right-click it and select Run as administrator.
  2. Run the command below. Restart Windows when requested.
Windows · Administrator PowerShell
wsl --install -d Ubuntu

Open Ubuntu from Start. Finish its first-time setup by choosing a Linux username and password. No characters appear while typing the password; this is normal. The Linux account is separate from your Windows account.

Windows · PowerShell
wsl --list --verbose

Look for Ubuntu with VERSION 2. If it shows 1, use wsl --set-version Ubuntu 2 in PowerShell. Use the exact distribution name shown in the list. If installation reports disabled virtualisation, follow your computer manufacturer’s instructions to enable it in UEFI/BIOS.

1A · Clean reads and assign taxonomy

Detailed steps for run_metabarcoding_pipeline.sh: Inputs and sample folder layout · Settings and configuration · Preview, run and follow progress · Prepare the SINTAX database once · Clean and combine FASTQ reads · Classify cleaned reads with SINTAX · Reuse, interrupted runs and regeneration · Output checklist and troubleshooting. Search the left menu by script name, input, output filename, setting or error message.

Input: raw *.fastq.gz files. Output: cleaned reads and SINTAX taxonomic labels. Existing completed outputs are reused by default.

Review configuration first:

Ubuntu · Bash
cat config/pipeline.env

The current defaults use fastplong quality filtering, adapter trimming and read lengths of 300–1,900 nt. SINTAX considers 300–2,000 nt, both strands, a fixed seed of 666 and the configured MIDORI reference. These are protocol-specific settings, not universal thresholds.

Preview one sample without running the analysis:

Ubuntu · Bash
bash code/run_metabarcoding_pipeline.sh --dry-run data/mergedseq5/barcode01

Then process that sample, or process the whole selected range:

Ubuntu · Bash
bash code/run_metabarcoding_pipeline.sh data/mergedseq5/barcode01
Ubuntu · Bash
bash code/run_metabarcoding_pipeline.sh mergedseq5

For a raw unclassified folder, the cleaning/classification script also accepts:

Ubuntu · Bash
bash code/run_metabarcoding_pipeline.sh data/mergedseq5/unclassified

What happens: the reference is decompressed only when needed; a missing UDB is built once. Cleaned reads are combined into filtered/asinput.fastq.gz. Results go to data/sintax/FOLDER/FOLDER_sintaxSP.tsv. fastplong HTML reports are in the sample’s filtered/ folder.

Use a unique output root for a different sequencing dataset: the sample basename determines SINTAX output names. For example, set SINTAX_OUTPUT_ROOT=data/sintax_newdataset before the command and configure subsequent analysis accordingly. Do not use FORCE=1 casually; it requests regeneration.

The classifier’s configured cutoff is 1; the post-classification analysis independently uses the recorded per-rank confidence at ≥0.80. Read processing does not generate consensus sequences or perform the protein-length screen.

1A.1 · Inputs and sample folder layout

Merge pass/fail reads before analysis

For layouts such as mergedseq5/barcode01/pass/*.fastq.gz and mergedseq5/barcode01/fail/*.fastq.gz, run this once before analysis. It also handles unclassified, passed/failed, fastq_pass/fastq_fail and the alternative layout mergedseq5/pass/barcode01/.

Ubuntu · Bash
python code/merge_pass_fail.py mergedseq5 --dry-run
python code/merge_pass_fail.py mergedseq5

The helper writes pass_fail_merged.fastq.gz directly inside each sample, preserving the original files and recording their paths/sizes/modification times. It accepts gzip FASTQ only. Repeating unchanged merges reuses the result. Existing other direct raw FASTQs or previous analyses cause an error to prevent double counting or stale results; changed inputs need a fresh dataset. Read processing applies its own quality filtering to the combined passed and failed reads. Already-flat sample folders need no merge.

Run everything with the parent folder

Any dataset name works: sequencing2 is as valid as mergedseq5. A bare name resolves under data/; full paths can point elsewhere. No dataset name needs to begin with merged. For example:

Ubuntu · Bash
python code/merge_pass_fail.py sequencing2 --dry-run
python code/merge_pass_fail.py sequencing2
python code/read_processing.py sequencing2 --output-dir data/read_processing/sequencing2_run01
python code/postprocess_sintax.py sequencing2 --bold --taxon Tipulidae --analysis-dir data/read_processing/sequencing2_run01/analysis --output-dir data/postprocessing/Tipulidae_sequencing2_run01 --threads 8

Read-processing defaults to data/sintax/sequencing2/ for this dataset's classification files. Barcode and unclassified names stay unchanged inside the parent. Folder names do not determine biological metadata: supply configured adapter/primer FASTAs appropriate to the experiment; barcode folder names supply sample identity.

A bare mergedseq5 resolves to data/mergedseq5; full paths work too (quote spaces). The launcher discovers nonempty barcodeNN and unclassified folders. It runs cleaning, SINTAX, primer detection, best-hit parsing and every analysis notebook:

Ubuntu · Bash
conda activate taxonomy
python code/read_processing.py mergedseq5 --dry-run
python code/read_processing.py mergedseq5 --output-dir data/read_processing/mergedseq5_run01
python code/postprocess_sintax.py mergedseq5 --bold --taxon Tipulidae --analysis-dir data/read_processing/mergedseq5_run01/analysis --output-dir data/postprocessing/Tipulidae_run01 --threads 8

Prepare raw reads, adapter/primer FASTAs and reference databases first. Read processing writes analysis/, primertrack/ and executed notebooks under its new run directory; omit --output-dir for a timestamped run. Classification defaults to data/sintax/DATASET/, keeping barcode outputs from separate datasets apart. Use --sintax-root PATH for a custom location; explicitly select --sintax-root data/sintax for legacy outputs directly under that root. Barcode folder names identify samples; no PCR mapping file is required. For an interrupted launcher, use a new run output directory; completed cleaning/classification/primer-hit files are reused.

Unclassified: its read-level analysis is included under its own source folder. It contributes neither a barcode nor taxon presence to barcode contamination prevalence. Flags inferred from analysed barcode folders can still annotate its reads. With no analysed barcodes, no cross-barcode flags are inferred. Missing primer-hit records remain unknown. Postprocessing includes only folders in the completed analysis, so older analyses need regeneration to add previously omitted unclassified.

run_metabarcoding_pipeline.sh accepts one or more dataset parents or individual sample folders. It discovers immediate barcodeNN and unclassified folders, skips empty/non-sample folders, and rejects duplicate sample names across parents. Each folder basename, such as barcode01 or unclassified, becomes its output identifier.

1A.4 · Prepare the SINTAX database once

Download MIDORI and place it in the project

Open the official MIDORI download page. Follow Previous releases to Zenodo and select GB272 (June 2026) for the current configuration. Select SINTAX → UNIQ → NUC_SP → CO1, download the containing archive, and extract the matching reference file. Preserve its taxonomy headers. For a newer release, keep its real filename and update the configuration.

Ubuntu · Bash
mkdir -p data/sintax

Place MIDORI2_UNIQ_NUC_SP_GB272_CO1_SINTAX.fasta or its .fasta.gz sibling in data/sintax/. Unpack outer ZIP/TAR archives first. Manual gzip decompression is optional: when the UDB and plain FASTA are absent, Read processing decompresses the gzip FASTA and builds the UDB. To decompress manually while preserving the download:

Ubuntu · Bash
gzip -dk data/sintax/MIDORI2_UNIQ_NUC_SP_GB272_CO1_SINTAX.fasta.gz

1A.6 · Classify cleaned reads with SINTAX

Input: the sample’s filtered/asinput.fastq.gz and the configured UDB. Process: VSEARCH SINTAX with --sintax_random, both strands, cutoff 1, seed 666, eight threads and length bounds 300–2,000 nt by default.

The classifier writes to a temporary TSV in the target output folder. The final TSV is published after VSEARCH succeeds. Temporary classifier output is removed on ordinary failure/exit; an abrupt system shutdown may leave temporary files, which are not completed results.

Field in the tab-delimited SINTAX fileMeaning
1 · Query ID/headerIdentity of the cleaned sequence being classified.
2 · Candidate taxonomyTaxonomic ranks and bootstrap confidences in parentheses.
3 · StrandClassifier strand information.
4 · Accepted taxonomyLabels passing the classifier cutoff. This may differ from the notebook’s independently recomputed ≥0.80 assignment.

Raw SINTAX TSVs are machine outputs without a column-header row; the later analysis tables do have column names. Do not add a header to a classifier file manually.

Ubuntu · Bash
head -n 3 data/sintax/mergedseq5/barcode01/barcode01_sintaxSP.tsv

Output naming is SINTAX_OUTPUT_ROOT/SAMPLE/SAMPLE_SUFFIX.tsv. For the defaults: data/sintax/mergedseq5/barcode01/barcode01_sintaxSP.tsv. Read IDs are needed for the primer joins, cleaned-read exports and later analyses.

This script stops after classification. It does not calculate contamination flags, run notebooks, detect primers, translate reads or infer trees. Continue with primer tracking and post-classification notebooks.

1A.7 · Reuse, interrupted runs and regeneration

This shell script has no --resume option. Run the same command again to use its existing-file checks. This differs from Postprocessing’s hash-based checkpoints.

A.6 Choose and prepare the COI coding guide for kc-align

This is not automatically supplied by the archive or by the BOLD database. Prepare it before running A.7. Use a trustworthy sequence from NCBI or BOLD, verify the precise COI coding interval, exclude suspected NUMTs and remove primers. These full instructions are repeated here so you can stay in Route A.

Choose a trustworthy source

Use an identified specimen from the same species, if available, or a closely related species in the same genus or family that covers the same COI region. Prefer a curated or published record with specimen/voucher information and supporting evidence that it is mitochondrial COI. Do not automatically use the first search result, an unverified sequence, or a local consensus you are trying to identify. A file already in coi_refs/ is not proof of suitability for your taxon.

From NCBI: search NCBI Nucleotide for your group and COI, COX1 or cytochrome c oxidase subunit I. Inspect the GenBank record, its mitochondrial source, publication, specimen and CDS annotation (the protein-coding DNA feature). Check its strand, exact coordinates, codon_start, translation and genetic code. Download the nucleotide sequence of that COI feature or a verified target-region extract, not the protein FASTA or an entire mitochondrial genome containing other genes. An annotated mitochondrial genome can be a source for extracting COI even though whole genomes are normally excluded from Module 2's comparison-reference download. See NCBI's explanation of GenBank features.

From BOLD: select a named-species COI record with credible specimen identification, voucher/institution information and, where available, trace data and a supporting publication or linked GenBank record. Check the marker and sequence quality, and download the nucleotide FASTA. The bulk database header alone does not establish the exact coding boundaries or rule out a NUMT. If the BOLD barcode lacks coding annotation, align it to a trustworthy annotated mitochondrial COI sequence to establish its frame and precise target interval, or ask the maintainer for a prepared guide.

Exclude suspected NUMTs

A NUMT is a copy of mitochondrial DNA present in the nuclear genome. The guide should be genuine mitochondrial COI, not a NUMT, pseudogene, contaminant or chimera. Check the source annotation and evidence of mitochondrial origin. Compare its protein translation and nucleotide alignment with independently trusted COI records. Reject suspected NUMTs, unexpected frameshifts, internal stops or unexplained insertions/deletions.

No internal stops is necessary but not sufficient. Some NUMTs retain an apparently intact reading frame. A database name or a successful pipeline check cannot certify that the guide is NUMT-free. If the evidence is uncertain, choose a better documented record rather than calling it verified. This limitation is supported by research on insect COI NUMTs.

Prepare the exact COI coding region, without primers

Use the exact expected COI open reading frame (ORF) or the precisely defined coding interval being analysed. Establish its boundaries from annotation and known codon positions, not by guessing a length. There is no single universal COI length for all taxa and all assays.

  • If your analysis uses the complete COI ORF, use the complete annotated COI coding sequence of the expected length for that record/taxon, in the correct orientation. A short COI-5P barcode is not a complete COI ORF.
  • If your reads cover only a COI barcode fragment, use a verified, in-frame extract corresponding to that same region. It must start and finish on complete codon boundaries, with its exact expected coding length documented. Do not use an unrelated fragment or assume a fixed barcode length establishes the frame.
  • Remove laboratory primers, primer tails, tags, adapters and flanking non-COI sequence. Use the known primer positions and coding annotation to define the interval; do not remove genuine COI bases solely because a short motif resembles a primer. The guide must contain only the intended biological coding region.
  • Save one nucleotide sequence in a plain FASTA file: one > header followed by ungapped A/C/G/T DNA, without N or other ambiguity codes. Keep it in the coding orientation. Its length must be divisible by three, and translation with the correct genetic code must contain no internal stop codons.
  • Do not add or delete arbitrary bases to make the length divisible by three. Resolve partial codons or incomplete mitochondrial stop annotations using the source annotation and a validated preparation, not automatic padding. A genuine terminal stop must agree with the annotated complete CDS; a barcode fragment does not need a start or terminal stop codon.

For the usual insect mitochondrial COI analysis, use genetic code 5. Confirm the correct code for other organisms. If you cannot verify the interval or its reading frame, obtain a prepared reference from the maintainer before proceeding.

B.6 Choose and prepare the COI coding guide for kc-align

The guide is a separate, single-sequence file. The database and the Module 1 analysis do not automatically prepare it. These full selection and checking instructions are repeated here so you can stay in Route B.

Choose a trustworthy source

Use an identified specimen from the same species, if available, or a closely related species in the same genus or family that covers the same COI region. Prefer a curated or published record with specimen/voucher information and supporting evidence that it is mitochondrial COI. Do not automatically use the first search result, an unverified sequence, or a local consensus you are trying to identify. A file already in coi_refs/ is not proof of suitability for your taxon.

From NCBI: search NCBI Nucleotide for your group and COI, COX1 or cytochrome c oxidase subunit I. Inspect the GenBank record, its mitochondrial source, publication, specimen and CDS annotation (the protein-coding DNA feature). Check its strand, exact coordinates, codon_start, translation and genetic code. Download the nucleotide sequence of that COI feature or a verified target-region extract, not the protein FASTA or an entire mitochondrial genome containing other genes. An annotated mitochondrial genome can be a source for extracting COI even though whole genomes are normally excluded from Module 2's comparison-reference download. See NCBI's explanation of GenBank features.

From BOLD: select a named-species COI record with credible specimen identification, voucher/institution information and, where available, trace data and a supporting publication or linked GenBank record. Check the marker and sequence quality, and download the nucleotide FASTA. The bulk database header alone does not establish the exact coding boundaries or rule out a NUMT. If the BOLD barcode lacks coding annotation, align it to a trustworthy annotated mitochondrial COI sequence to establish its frame and precise target interval, or ask the maintainer for a prepared guide.

Exclude suspected NUMTs

A NUMT is a copy of mitochondrial DNA present in the nuclear genome. The guide should be genuine mitochondrial COI, not a NUMT, pseudogene, contaminant or chimera. Check the source annotation and evidence of mitochondrial origin. Compare its protein translation and nucleotide alignment with independently trusted COI records. Reject suspected NUMTs, unexpected frameshifts, internal stops or unexplained insertions/deletions.

No internal stops is necessary but not sufficient. Some NUMTs retain an apparently intact reading frame. A database name or a successful pipeline check cannot certify that the guide is NUMT-free. If the evidence is uncertain, choose a better documented record rather than calling it verified. This limitation is supported by research on insect COI NUMTs.

Prepare the exact COI coding region, without primers

Use the exact expected COI open reading frame (ORF) or the precisely defined coding interval being analysed. Establish its boundaries from annotation and known codon positions, not by guessing a length. There is no single universal COI length for all taxa and all assays.

  • If your analysis uses the complete COI ORF, use the complete annotated COI coding sequence of the expected length for that record/taxon, in the correct orientation. A short COI-5P barcode is not a complete COI ORF.
  • If your reads cover only a COI barcode fragment, use a verified, in-frame extract corresponding to that same region. It must start and finish on complete codon boundaries, with its exact expected coding length documented. Do not use an unrelated fragment or assume a fixed barcode length establishes the frame.
  • Remove laboratory primers, primer tails, tags, adapters and flanking non-COI sequence. Use the known primer positions and coding annotation to define the interval; do not remove genuine COI bases solely because a short motif resembles a primer. The guide must contain only the intended biological coding region.
  • Save one nucleotide sequence in a plain FASTA file: one > header followed by ungapped A/C/G/T DNA, without N or other ambiguity codes. Keep it in the coding orientation. Its length must be divisible by three, and translation with the correct genetic code must contain no internal stop codons.
  • Do not add or delete arbitrary bases to make the length divisible by three. Resolve partial codons or incomplete mitochondrial stop annotations using the source annotation and a validated preparation, not automatic padding. A genuine terminal stop must agree with the annotated complete CDS; a barcode fragment does not need a start or terminal stop codon.

For the usual insect mitochondrial COI analysis, use genetic code 5. Confirm the correct code for other organisms. If you cannot verify the interval or its reading frame, obtain a prepared reference from the maintainer before proceeding.

C.2 Understand which reads are kept

The program performs these steps automatically:

  1. Extract your reads. Select the requested organism group from the chosen barcode folders, using the identifications recorded by Module 1.
  2. Keep the highest-count identification per barcode + forward primer. The assumption is one insect for each such pair. Counts are added across reverse primers. For example, counts of 37 for Tipula tipula, 10 for Tipula spectra and 2 for Tipula nigris retain the 37 Tipula tipula reads. If labels tie for the largest total, all tied labels and their reads are retained. Lower-count labels do not continue. This is calculated only among the extracted reads; the winner need not exceed half the total and is not proof of species identity.
  3. Group similar sequences. Local reads cluster at 97% identity, separately by barcode, forward primer and retained label. Each cluster produces a *consensus*: a summary DNA sequence built from its reads. A broad genus-level assignment can hide different species, so sequence similarity is still checked. Reference sequences cluster at 98%, only within the same taxonomic label; different reference species never share a cluster. Local and reference reads are kept separate during clustering.
  4. Check protein-coding DNA. For the usual insect COI analysis, keep the default protein check. It requires at least 200 amino acids in a row without a stop or unknown letter in one possible reading frame, using genetic code 5. Passing does not prove that the sequence is genuine mitochondrial COI.
  5. Align and trim. For COI, prefer kc-align with a prepared coding guide; MAFFT runs if you omit that option. The aligner lines up corresponding DNA. ClipKIT removes columns with many gaps. Both steps are automatic.
  6. Estimate and draw the tree. IQ-TREE estimates the tree and Baltic draws it. Bootstrap replicates are disabled, so new trees do not have bootstrap support. The picture is midpoint rooted: its root is placed halfway along the longest path between tips. This does not establish the organisms' biological ancestor.

Primer removal needs attention: tracking a primer is not the same as removing it. The current MAFFT workflow has no general primer-removal step. If primer sequences remain in your reads, arrange a suitable removal workflow or have the alignment reviewed before interpreting the resulting tree. Removing gap-heavy columns is not a substitute for primer removal.

Optional reference: Coding-guide technical reference
Postprocessing · preferred COI method

Coding-guide technical reference

For COI, kc-align is the preferred alignment choice in this project when a trustworthy coding reference is available. MAFFT remains the software default: leaving off --kcalign still runs MAFFT. For noncoding DNA, use MAFFT rather than kc-align. The coding guide is a separate input from the BOLD/NCBI comparison sequences downloaded for the tree; choosing --download does not prepare the coding guide automatically.

1. Choose a trustworthy source

Use an identified specimen from the same species, if available, or a closely related species in the same genus or family that covers the same COI region. Prefer a curated or published record with specimen/voucher information and supporting evidence that it is mitochondrial COI. Do not automatically use the first search result, an unverified sequence, or a local consensus you are trying to identify. A file already in coi_refs/ is not proof of suitability for your taxon.

From NCBI: search NCBI Nucleotide for your group and COI, COX1 or cytochrome c oxidase subunit I. Inspect the GenBank record, its mitochondrial source, publication, specimen and CDS annotation (the protein-coding DNA feature). Check its strand, exact coordinates, codon_start, translation and genetic code. Download the nucleotide sequence of that COI feature or a verified target-region extract, not the protein FASTA or an entire mitochondrial genome containing other genes. An annotated mitochondrial genome can be a source for extracting COI even though whole genomes are normally excluded from Module 2's comparison-reference download. See NCBI's explanation of GenBank features.

From BOLD: select a named-species COI record with credible specimen identification, voucher/institution information and, where available, trace data and a supporting publication or linked GenBank record. Check the marker and sequence quality, and download the nucleotide FASTA. The bulk database header alone does not establish the exact coding boundaries or rule out a NUMT. If the BOLD barcode lacks coding annotation, align it to a trustworthy annotated mitochondrial COI sequence to establish its frame and precise target interval, or ask the maintainer for a prepared guide.

2. Exclude suspected NUMTs

A NUMT is a copy of mitochondrial DNA present in the nuclear genome. The guide should be genuine mitochondrial COI, not a NUMT, pseudogene, contaminant or chimera. Check the source annotation and evidence of mitochondrial origin. Compare its protein translation and nucleotide alignment with independently trusted COI records. Reject suspected NUMTs, unexpected frameshifts, internal stops or unexplained insertions/deletions.

No internal stops is necessary but not sufficient. Some NUMTs retain an apparently intact reading frame. A database name or a successful pipeline check cannot certify that the guide is NUMT-free. If the evidence is uncertain, choose a better documented record rather than calling it verified. This limitation is supported by research on insect COI NUMTs.

3. Prepare the exact COI coding region, without primers

Use the exact expected COI open reading frame (ORF) or the precisely defined coding interval being analysed. Establish its boundaries from annotation and known codon positions, not by guessing a length. There is no single universal COI length for all taxa and all assays.

  • If your analysis uses the complete COI ORF, use the complete annotated COI coding sequence of the expected length for that record/taxon, in the correct orientation. A short COI-5P barcode is not a complete COI ORF.
  • If your reads cover only a COI barcode fragment, use a verified, in-frame extract corresponding to that same region. It must start and finish on complete codon boundaries, with its exact expected coding length documented. Do not use an unrelated fragment or assume a fixed barcode length establishes the frame.
  • Remove laboratory primers, primer tails, tags, adapters and flanking non-COI sequence. Use the known primer positions and coding annotation to define the interval; do not remove genuine COI bases solely because a short motif resembles a primer. The guide must contain only the intended biological coding region.
  • Save one nucleotide sequence in a plain FASTA file: one > header followed by ungapped A/C/G/T DNA, without N or other ambiguity codes. Keep it in the coding orientation. Its length must be divisible by three, and translation with the correct genetic code must contain no internal stop codons.
  • Do not add or delete arbitrary bases to make the length divisible by three. Resolve partial codons or incomplete mitochondrial stop annotations using the source annotation and a validated preparation, not automatic padding. A genuine terminal stop must agree with the annotated complete CDS; a barcode fragment does not need a start or terminal stop codon.

For the usual insect mitochondrial COI analysis, use genetic code 5. Confirm the correct code for other organisms. If you cannot verify the interval or its reading frame, obtain a prepared reference from the maintainer before proceeding.

Protein screening details

For the usual insect COI analysis, leave this automatic check on. COI encodes a protein. The program tries the possible ways of reading each consensus DNA sequence and keeps it if one produces at least 200 amino acids in a row without a stop or an unknown letter. This helps screen suspicious sequences, but passing does not prove a sequence is genuine mitochondrial COI.

You do not need to understand reading frames to use the default check. It uses genetic code 5, appropriate to invertebrate mitochondria. Do not change the code or protein-length threshold just to make a failed run finish; first confirm that the marker and sequences are appropriate.

For a noncoding marker: this protein check is not appropriate. Use MAFFT with --skip-translation and a matching marker-specific database. This flag does not change which gene NCBI downloads. If you are unsure which marker you have, ask the person who prepared the reads.

Technical details and additional options (optional)

By default, SeqKit translates each combined consensus in all six frames using genetic code 5 (invertebrate mitochondrial). At least one frame must contain ≥200 consecutive amino acids, split at stops and unknown residues. --min-aa changes the threshold; --translation-table changes the code.

Accepted nucleotide sequences go to combined_TAXON_nonumt_DATE.fasta, with frame measurements in translation_lengths.tsv. “nonumt” is a filename convention: passing this screen does not prove that a sequence is free of NUMTs.

For nuclear/noncoding loci, use default MAFFT and --skip-translation. All consensuses then go to combined_TAXON_selected_DATE.fasta, with no six-frame file or translation-selection table. Both the local assignments and external database must be appropriate for that marker.

--download still searches COI. BOLD mode includes every matching marker. Use an appropriate nuclear reference dataset rather than treating the skip flag as a marker-selection option. kc-align still applies its own coding-sequence checks when the earlier translation screen is skipped.

At least four retained sequences are needed for phylogeny. The reference 500–2,000 nt filter remains active in all modes.

Optional reference: Alignment tool details
Postprocessing

Alignment tool details

An alignment places corresponding parts of the DNA sequences into columns. The program does this automatically before estimating the tree. Choose the alignment method when preparing your command.

For COI, prefer kc-align with a trustworthy coding guide. Follow the complete preparation and running instructions. MAFFT remains the software default if you omit --kcalign; use it for noncoding DNA.

MAFFT: software-default alternative

Without an alignment option, the program uses MAFFT. No extra reference file is needed. The worked examples above use this option. It works with nucleotide sequences, including noncoding markers when the protein screen is skipped.

Primer sequences need attention. Primer tracking identifies tags; it is not the same as removing every laboratory primer sequence from the reads. The current workflow does not have a general primer-removal step for MAFFT. If your reads still contain primer sequence, arrange an appropriate removal workflow or have the alignment reviewed before interpreting the resulting tree. ClipKIT's removal of gap-heavy columns is not a substitute for removing primers.

kc-align: preferred for COI with a verified guide

Use this only when you have a trusted, correctly prepared coding reference for your marker. Add --kcalign --kcalign-reference PATH to your command, replacing PATH with that file's path. A random downloaded sequence is not automatically a suitable guide.

The reference FASTA must contain exactly one DNA sequence, without gaps or ambiguous letters, starting at the correct codon boundary. Its length must be divisible by three, and it must have no internal stop codons under the chosen genetic code. It should not contain primer sequence. If you cannot verify its reading frame, obtain a prepared reference from the maintainer. Do not trim arbitrary letters simply to pass the checks.

For kc-align, use --threads 1 or a multiple of three, such as --threads 6. kc-align may reject sequences that fail its coding checks. Review *.kcalign_selection.tsv to see which were rejected. The guide reference helps the alignment but is not automatically added as an extra tree tip.

Technical details and additional options (optional)

MAFFT: default

Without an aligner flag, the module uses FFT-NS-2 nucleotide alignment with --retree 2 --maxiterate 0 --adjustdirectionaccurately --op 20 --ep 18. Tracking headers are restored after strand adjustment. This is the general choice for nuclear/noncoding loci.
