Overview

This project turns Oxford Nanopore (ONT) sequencing reads of the insect COI barcode gene into a draft alignment and phylogenetic tree that a person then reviews. It is written for biologists: every step can be run by copying commands, and the guides explain what each step does and what to check.

Open the offline browser guide (double-click the file; no internet or server needed) for a menu-driven version of these instructions with copy buttons and a command builder.

What the pipeline does

Each sequencing barcode folder (barcode01, barcode02, … as written by MinKNOW) holds the reads of one pool of PCR products. Inside a pool, each insect specimen was amplified with a different tagged forward primer (bc1001–bc1096) and one of three tagged reverse primers (bc1100rc, bc1107rc, bc1122rc). The tag tells you which specimen a read came from.

Read the map left to right. Each coloured line is one stream of data: your reads (blue), the tags that identify specimens (yellow), the MIDORI classification database (purple), the BOLD or NCBI reference sequences (orange), the optional COI guide for kc-align (pink) and a shared archive for collaborators who only run Module 2 (grey). Where lines run side by side through one step, that step uses both; the local reads become one consensus per specimen, the references are reduced to one centroid per ≥98% species cluster, and the two join at "Combine". Squares are files you provide; grey pills are key outputs; the shaded area is Module 2.

The pipeline never makes the final scientific decisions. You decide which reads, consensus sequences and reference species belong in the final tree.

Quick start

  1. Set up Ubuntu/WSL, Miniconda and the two software environments: setup guide.
  2. Download the classification database (MIDORI) and, for Module 2, the reference database (BOLD).
  3. Put your raw reads in data/DATASET/barcodeNN/ (one folder per barcode; any dataset name works) and run, from the project folder:
Ubuntu · Bash
conda activate taxonomy
# Only if MinKNOW wrote pass/fail subfolders: combine them first.
python code/merge_pass_fail.py DATASET
# Module 1: preview, then run.
python code/read_processing.py DATASET --dry-run
python code/read_processing.py DATASET --output-dir data/read_processing/DATASET_run01
# Module 2: one taxon.
python code/postprocess_sintax.py DATASET --bold --taxon Tipulidae \
  --analysis-dir data/read_processing/DATASET_run01/analysis \
  --output-dir data/postprocessing/Tipulidae_run01 \
  --kcalign --kcalign-reference data/postprocessing/coi_refs/COI_reference.fasta --threads 6
  1. Review the trimmed alignment and the tree: what to check.

Things to know before you start

  • Classification is the slow step. SINTAX can take days for a large barcode folder. Everything before and after it takes minutes to hours.
  • Tags must be complete to be trusted. A tag is assigned only when the read contains the whole tag with at most 4 errors and it clearly beats every other tag; otherwise the read is marked ambiguous, too_many_errors or truncated (details).
  • The BOLD database contains other markers (16S, 28S, ITS, COI-3P, CYTB…). If you do not use kc-align with a COI guide, references of other markers can end up in the alignment (details).
  • The first tree is a draft. It has no bootstrap support and has not been checked by a person.

Setup

You need to do this once per computer. All commands are typed in the Ubuntu window (WSL, the Windows Subsystem for Linux). If Ubuntu is not installed, follow Microsoft's WSL installation instructions.

1. Find your Windows folders from Ubuntu

Ubuntu sees the Windows C: drive as /mnt/c/. Replace USERNAME below with your Windows account folder name (run ls /mnt/c/Users to see it). For example, Windows C:\Users\USERNAME\Downloads is:

Ubuntu · Bash
cd /mnt/c/Users/USERNAME/Downloads
  • If Windows keeps Documents in OneDrive, the path is /mnt/c/Users/USERNAME/OneDrive/Documents.
  • Use forward slashes /, and put quotes around a path that contains spaces.
  • ~ means your Linux home folder, not your Windows user folder.
  • explorer.exe . opens the current Ubuntu folder in Windows Explorer.

2. Install Miniconda (the software manager)

If conda --version already prints a version, skip this step.

Ubuntu · Bash
sudo apt update && sudo apt install -y curl ca-certificates bzip2 util-linux git
cd ~
curl -fLO https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
sha256sum Miniconda3-latest-Linux-x86_64.sh

Compare the printed checksum with the one listed beside that file on the Miniconda download page; continue only if they match. Then run the installer, accept the default location (~/miniconda3) and say yes to initialising Bash:

Ubuntu · Bash
bash Miniconda3-latest-Linux-x86_64.sh

Choose where the project lives before you start analysing; moving it later is possible but large data folders are slow to move.

MIDORI database

Module 1 classifies reads with VSEARCH SINTAX against the MIDORI COI database. The database is large and stays on your computer; it is not stored in Git.

Download the right file

  1. Open the MIDORI download page.
  2. To reproduce this project's settings, choose Previous releases, then GB272 (June 2026). (For a newer release, keep its real release number in the file name and update config/pipeline.env, see below.)
  3. Select the combination SINTAX · UNIQ · NUC_SP · CO1 and download it. - SINTAX is the file format VSEARCH needs; other formats (BLAST, RAW…) do not work. - NUC_SP contains nucleotide sequences, including records with ambiguous species names. - CO1 is the COI marker.
  4. If the download is a ZIP or TAR archive, unpack it and keep only MIDORI2_UNIQ_NUC_SP_GB272_CO1_SINTAX.fasta (or its .fasta.gz).

Write down the release, download date and link. Cite MIDORI as its website asks.

Put it in place

Ubuntu · Bash
cd ~/metabarcoding
mkdir -p data/sintax
mv "/mnt/c/Users/USERNAME/Downloads/MIDORI2_UNIQ_NUC_SP_GB272_CO1_SINTAX.fasta.gz" data/sintax/

Either data/sintax/MIDORI2_UNIQ_NUC_SP_GB272_CO1_SINTAX.fasta or the same name with .gz works. The first time classification runs, the pipeline unpacks a .gz copy (it keeps the original) and builds a VSEARCH index file, …_SINTAX.udb. This takes a while and needs free disk space for both: the GB272 index is about 10 GB.

Using another release

Change these three settings in config/pipeline.env together, so new results are not mixed with old ones:

Ubuntu · Bash
SINTAX_REFERENCE=data/sintax/MIDORI2_UNIQ_NUC_SP_GB999_CO1_SINTAX.fasta
SINTAX_DB=data/sintax/MIDORI2_UNIQ_NUC_SP_GB999_CO1_SINTAX.udb
SINTAX_SUFFIX=sintaxGB999

An existing .udb is reused without checking which FASTA it came from, so never rename a new release to an old name.

Optional: an Arthropoda-only database

Keeping only arthropod records makes the database smaller and SINTAX faster. Done for this project on 23 Nov 2026, in the taxonomy environment, from data/sintax/:

Ubuntu · Bash
# Keep records whose phylum field is exactly Arthropoda (NCBI taxid 6656).
seqkit grep -n -r -p ',p:Arthropoda_6656,' \
  MIDORI2_UNIQ_NUC_SP_GB272_CO1_SINTAX.fasta > MIDORI2_UNIQ_NUC_SP_GB272_CO1_ARTH_SINTAX.fasta
grep -c '^>' MIDORI2_UNIQ_NUC_SP_GB272_CO1_ARTH_SINTAX.fasta   # GB272: 2,432,079 of 3,191,213

# Build the VSEARCH index for the subset.
vsearch --makeudb_usearch MIDORI2_UNIQ_NUC_SP_GB272_CO1_ARTH_SINTAX.fasta \
  --output MIDORI2_UNIQ_NUC_SP_GB272_CO1_ARTH_SINTAX.udb \
  --notrunclabels
  • Match the phylum field, not the word. MIDORI writes the phylum as p:Arthropoda_6656. A pattern such as \bArthropoda\b does not match it, because regular expressions count _ as part of a word. That pattern keeps only the ~1,000 unidentified Arthropoda sp. records, and the index looks fine but is useless. Always check the record count with grep -c '^>', as above.
  • Expect about a quarter less work. Arthropods are 76% of the GB272 COI records, so SINTAX time drops by roughly that share, not several-fold.
  • Non-arthropod reads get forced into arthropods. SINTAX can only choose among the names in the database. Reads from fungi, plants, vertebrates or bacteria are then given an arthropod name, sometimes with high confidence at high ranks. Use the subset only when such reads are of no interest. Do not use it when you need to report or remove them.
  • Keep the results apart. Set the three settings together in config/pipeline.env, for example SINTAX_SUFFIX=sintaxARTH, and pass --suffix sintaxARTH to sintax_analysis.py. Results made with the full database are named …_sintaxSP.tsv.

Classification results are written to data/sintax/DATASET/barcodeNN/barcodeNN_sintaxSP.tsv (see Module 1).

Module 1 · Read processing

Module 1 takes the raw reads of every barcode folder in a sequencing run and produces, for each read: which tagged primers it carries, a cleaned and primer-free sequence, and a taxonomic identification. It then summarises the results per sample and flags taxa that appear in almost every sample (possible contamination).

Before starting, complete the setup and download the MIDORI database.

How long it takes: finding primers and tags takes 1–2 minutes per 500,000 raw reads. Quality filtering takes about 15–30 minutes for the same number, almost all of it spent searching for ONT barcodes inside reads. Classification (SINTAX) is far slower: about one read per second on 8 threads, which is hours to weeks per sample.

What happens to each sample

Each sample
  1. Raw reads barcodeNN/*.fastq.gz
  2. cutadapt: find the forward and reverse primer cores; turn reads to one direction; cut off everything outside the primers
  3. primer_tags.py: compare the 21 bases next to each primer with all tags; assign a tag or a status
  4. fastplong: remove low-quality and too short/long reads; remove leftover ONT barcodes; split chimeric reads
  5. VSEARCH SINTAX: taxonomy of every read with a confidence for each rank
  6. Analysis tables and figures
  1. Primers. cutadapt looks for the forward primer core (RKTCAACMAATCATAAAGATATTGG) and the reverse primer core (TAAACTTCWGGRTGWCCAAAAAATCA, found as its reverse complement at the other end). It understands degenerate bases (R, K, M, W…) and allows up to PRIMER_CORE_MAX_ERRORS = 5 errors per core. Reads that face the wrong way are reverse-complemented, so all output reads have the same direction. The primers, tags and everything beyond them (adapters, barcodes) are cut off.
  2. Tags. See How tags are identified.
  3. Quality filter. fastplong removes reads with mean quality below 6, too many low-quality bases, or a length outside 300–1,900 nt. It removes remaining ONT barcode sequences and splits reads that contain an internal adapter (chimeras); the pieces are named chimera-segment-1-…, chimera-segment-2-… (older fastplong versions: split-by-adapter-left-…/-right-…).
  4. Classification. VSEARCH SINTAX compares every cleaned read with the MIDORI COI database and reports, for each rank from domain to species, a name and a confidence between 0 and 1.

Tags are identified on the raw reads, before fastplong, because fastplong's adapter removal would cut into the tags.

How tags are identified

Each primer starts with a 21-base tag block (GGTAG spacer + 16-base tag). After cutadapt has found a primer core, the bases next to it are compared with every known tag block, allowing substitutions, insertions and deletions (an edit distance). The result for each read end is one of:

StatusMeaningTag reported?
assignedThe best tag has at most TAG_MAX_ERRORS = 4 errors, and the second-best tag has at least TAG_MIN_MARGIN = 2 more errors.yes
ambiguousTwo or more tags fit almost equally well (less than 2 errors apart). The candidates are listed in *_tag_candidates.no
too_many_errorsEven the best tag has more than 4 errors, e.g. a damaged tag or a primer used without a tag.no
truncatedThe read starts or ends inside the tag block, so fewer than TAG_MIN_OBSERVED = 21 tag bases are present.no
primer_not_foundcutadapt found no primer core at this end.no

Why these limits: forward tags differ from each other at as few as 5 positions, so a tag with more than 4 errors could be confused with another one. ONT reads often contain insertions and deletions, so a comparison that only counts mismatches (as the old pipeline did) shifts out of register and picks the wrong tag. In a test on 15,793 barcode01 reads the old method disagreed with this one for 5.6% of forward tags, and the disagreeing calls were the old method's errors.

About the 16-error limit used previously: the old setting allowed 16 mismatches over the whole 46-base primer, partly because seqkit counted every degenerate base as a mismatch. cutadapt handles degenerate bases correctly, so the primer core gets its own limit (5), and the tag block its own (4). Allowing many more core errors is unsafe: in a test with 12, cutadapt "found" primers at random positions in every read and cut away 98% of the sequence.

Open .tsv files in a spreadsheet and choose Tab as the separator. The read tables are large; filter them in Python or R rather than a spreadsheet if needed.

Confidence and assigned taxon

SINTAX reports a confidence for every rank. A rank is accepted when its confidence is at least 0.8. The assigned taxon is the lowest accepted rank (for example the genus, if species is below 0.8). taxonomy_status is taxapass when that rank is genus or species, otherwise taxafail. Confidences are SINTAX bootstrap values, not probabilities.

Contamination screen

A taxon (at any rank) is flagged contamination when it is confidently found in at least 80% of the barcode folders analysed (unclassified is not counted). For 21 barcodes that means 17 or more. This is only a warning sign: widespread insects and broad ranks such as Insecta are naturally found everywhere.

Read counts

read_count counts cleaned reads. A raw read split by fastplong into two pieces counts twice; raw_read_count counts each raw read once. Tags are looked up for the raw read, so both pieces carry the same tags.

When results already exist

The pipeline reuses finished work:

  • A sample is cleaned again only when filtered/asinput.fastq.gz or filtered/primer_tags.tsv.gz is missing, or with FORCE=1.
  • A filtered/ folder made by an older pipeline version is not overwritten automatically: the run stops and asks for FORCE=1.
  • A sample is classified again when its SINTAX output is missing or older than its cleaned reads, or with FORCE_SINTAX=1.
  • The analysis tables are always written to a new folder.

To redo only the tables (for example with another prevalence threshold) without cleaning or classifying:

Ubuntu · Bash
python code/sintax_analysis.py DATASET --output-dir data/read_processing/DATASET_tables02 --prevalence 0.9

BOLD database

Run commands from the repository root with the taxonomy environment active. The database stays local and is excluded from Git; commit this README instead. Postprocessing needs it only for --bold; --download obtains references from NCBI.

Download and prepare an updated BOLD database

Do this before running Module 2 with --bold. A database downloaded earlier does not update itself. The following steps prepare a new snapshot without editing the pipeline code.

1. Download the sequence file

Open the latest BOLD data package in your web browser. If that address is unavailable, open the BOLD Data Packages page and choose Latest. Download the FASTA sequence file, rather than the TSV data table or JSON metadata. If BOLD requests sign-in, follow its access instructions.

Save the download in your normal Downloads folder and note its release date, original filename and source link. “Latest” changes over time; keeping these notes lets you identify which release you used. If the download is an outer ZIP or TAR archive, extract it and locate the sequence FASTA first. An actual .fasta.gz sequence file can stay compressed. Renaming a TSV file to .fasta.gz does not convert it into sequence data.

2. Open Ubuntu and locate the download

Go to your metabarcoding project folder and activate the environment. Change the first line if the project is stored elsewhere:

Ubuntu · Bash
cd ~/metabarcoding
conda activate taxonomy
seqkit version

If you downloaded through Windows, list the Downloads folder from Ubuntu:

Ubuntu · Bash
ls -lh "/mnt/c/Users/USERNAME/Downloads/"

Replace USERNAME with the Windows account folder name. For a download made inside Linux, use ls -lh ~/Downloads/ instead. Find the actual FASTA filename. In the next command, replace the entire example input path with that file. DOWNLOAD_DATE below is a placeholder, not a required part of the name.

3. Remove records that have a header but no DNA sequence

A FASTA record starts with a line beginning with >, followed by its DNA letters. Some BOLD records have a header but no letters. Use SeqKit to remove those empty records before the pipeline reads the database:

Ubuntu · Bash
mkdir -p data/bold data/bold_staging
seqkit seq --min-len 1 \
  "/mnt/c/Users/USERNAME/Downloads/BOLD_Public.DOWNLOAD_DATE.fasta.gz" \
  -o data/bold_staging/BOLD_download.filtered.fasta.gz

The input can be plain FASTA or gzipped FASTA. SeqKit writes compressed output because the output name ends in .gz; you do not need to decompress the input or compress the result separately. Keep input and output as different files. The staging folder is outside data/bold/, so the pipeline will not accidentally scan a file while you are preparing it.

--min-len 1 means “keep sequences at least one DNA letter long.” It removes zero-length records, keeps the full headers of retained records, and does not select species, remove duplicates or apply the later reference-length filter. See the SeqKit command documentation.

Check the filtered file before continuing:

Ubuntu · Bash
seqkit stats data/bold_staging/BOLD_download.filtered.fasta.gz
gzip -t data/bold_staging/BOLD_download.filtered.fasta.gz

The statistics should show at least one sequence and a minimum sequence length of at least 1. gzip -t normally prints nothing when successful; an error means you should fix or repeat preparation before proceeding. For large databases, filtering and these checks can take time. Keep the terminal open and wait for the prompt to return. If SeqKit reports an error, do not continue with its output.

4. Give the prepared database a clear name and put it in the right folder

Use this command to move and rename the filtered file:

Ubuntu · Bash
mv -i data/bold_staging/BOLD_download.filtered.fasta.gz data/bold/BOLD_filtered.fasta.gz
ls -lh data/bold/BOLD_filtered.fasta.gz

The file is now called BOLD_filtered.fasta.gz inside data/bold/. If that filename already exists, mv -i asks before replacing it. Enter n to keep the existing file, or y only if you intend to replace it with the new one. If you chose n, the new file remains in the staging folder. Keep a dated copy or move the old version outside data/bold/ if you need to preserve it.

There is no required date or fixed database basename in the scripts. BOLD_filtered.fasta.gz is the standard name used in these instructions, not a hard-coded requirement. The default folder search accepts .fasta.gz, .fa.gz and .fna.gz. You can keep the real release date in your filename instead and use that name in --bold-db. Do not rename a new release with an old release's date simply to match an older example.

5. Tell Module 2 to use the prepared file

Add --bold-db data/bold/BOLD_filtered.fasta.gz to your BOLD command. For example:

Ubuntu · Bash
python code/postprocess_sintax.py --bold \
  --bold-db data/bold/BOLD_filtered.fasta.gz \
  --taxon Tipulidae --folders barcode15 \
  --analysis-dir data/read_processing/DATASET_run01/analysis \
  --output-dir data/postprocessing/Tipulidae_barcode15_bold_updated_run01 \
  --threads 6

Replace the taxon, barcode, completed analysis path and new results folder with your own choices. If an old command explicitly names an older database after --bold-db, change that argument to the new file; renaming another file does not update the command automatically. In the HTML guide's command builder, enter the same path in the BOLD database field.

Without --bold-db, the script scans all supported files in data/bold/. Keep only the intended prepared snapshot there when using that default; raw, filtered and old copies together can include the same records more than once. Specifying the prepared file explicitly is the clearest way to select a release. Start a new Module 2 run when changing the database; do not resume a run using a different snapshot.

Empty-record removal is a preparation step, not a species-identification check; see How Module 2 selects BOLD records.

How Module 2 selects BOLD records

Keep the full original FASTA headers. Their structure is:

text
>processID|marker|country|comma-separated lineage

Module 2 (--bold --taxon NAME) selects every record whose header contains NAME (not case-sensitive), anywhere in the header. --taxon Tipula therefore also selects Tipulidae records; this is intended, so that a genus search brings in its family as context. Use a taxon name, not a numeric taxid.

Only records with a named species are kept: the eighth lineage field (species) must be a proper binomial (optionally with subgenus or subspecies). Genus-only, empty and provisional names (sp., spp., cf., aff., nr. …) are excluded. Selected records are then length-filtered (500–2,000 nt) and clustered at 98% identity within each species; different species never share a consensus. The selected references and their metadata are written into each run folder, not here.

Other markers in the BOLD file

The BOLD file is not COI-only. In the 16-Oct-2026 snapshot, 20.5 million records are COI-5P (the barcode region) and about 1.5 million (6.5%) are other markers, for example ITS, COI-3P, 18S, matK, rbcL, CYTB, 16S, 28S, COII and the ND genes. Module 2 does not filter by marker, so records of other markers whose header contains your taxon name are selected as references.

  • The protein check removes most non-coding markers (ITS, 16S, 18S, 28S), because they rarely contain 200 amino acids without a stop codon.
  • Protein-coding markers (COI-3P, CYTB, COII, ND genes) can pass it. kc-align with a COI guide normally rejects them, because they do not align to COI.
  • If you use MAFFT, or --skip-translation, other markers can remain in the alignment and the tree. Look for references that do not line up with the COI sequences during review, and check their marker in bold_reference_metadata.tsv (column marker).

COI guide for kc-align

For COI, kc-align is the preferred alignment choice in this project when a trustworthy coding reference is available. MAFFT remains the software default: leaving off --kcalign still runs MAFFT. For noncoding DNA, use MAFFT rather than kc-align. The coding guide is a separate input from the BOLD/NCBI comparison sequences downloaded for the tree; choosing --download does not prepare the coding guide automatically.

1. Choose a trustworthy source

Use an identified specimen from the same species, if available, or a closely related species in the same genus or family that covers the same COI region. Prefer a curated or published record with specimen/voucher information and supporting evidence that it is mitochondrial COI. Do not automatically use the first search result, an unverified sequence, or a local consensus you are trying to identify. A file already in coi_refs/ is not proof of suitability for your taxon.

From NCBI: search NCBI Nucleotide for your group and COI, COX1 or cytochrome c oxidase subunit I. Inspect the GenBank record, its mitochondrial source, publication, specimen and CDS annotation (the protein-coding DNA feature). Check its strand, exact coordinates, codon_start, translation and genetic code. Download the nucleotide sequence of that COI feature or a verified target-region extract, not the protein FASTA or an entire mitochondrial genome containing other genes. An annotated mitochondrial genome can be a source for extracting COI even though whole genomes are normally excluded from Module 2's comparison-reference download. See NCBI's explanation of GenBank features.

From BOLD: select a named-species COI record with credible specimen identification, voucher/institution information and, where available, trace data and a supporting publication or linked GenBank record. Check the marker and sequence quality, and download the nucleotide FASTA. The bulk database header alone does not establish the exact coding boundaries or rule out a NUMT. If the BOLD barcode lacks coding annotation, align it to a trustworthy annotated mitochondrial COI sequence to establish its frame and precise target interval, or ask the maintainer for a prepared guide.

2. Exclude suspected NUMTs

A NUMT is a copy of mitochondrial DNA present in the nuclear genome. The guide should be genuine mitochondrial COI, not a NUMT, pseudogene, contaminant or chimera. Check the source annotation and evidence of mitochondrial origin. Compare its protein translation and nucleotide alignment with independently trusted COI records. Reject suspected NUMTs, unexpected frameshifts, internal stops or unexplained insertions/deletions.

No internal stops is necessary but not sufficient. Some NUMTs retain an apparently intact reading frame. A database name or a successful pipeline check cannot certify that the guide is NUMT-free. If the evidence is uncertain, choose a better documented record rather than calling it verified. This limitation is supported by research on insect COI NUMTs.

3. Prepare the exact COI coding region, without primers

Use the exact expected COI open reading frame (ORF) or the precisely defined coding interval being analysed. Establish its boundaries from annotation and known codon positions, not by guessing a length. There is no single universal COI length for all taxa and all assays.

  • If your analysis uses the complete COI ORF, use the complete annotated COI coding sequence of the expected length for that record/taxon, in the correct orientation. A short COI-5P barcode is not a complete COI ORF.
  • If your reads cover only a COI barcode fragment, use a verified, in-frame extract corresponding to that same region. Module 1 cuts the primers off, so for this project's primers the reads span the ~658 nt between the forward primer (…TCAACMAATCATAAAGATATTGG) and the reverse primer (TAAACTTCWGGRTGWCCAAAAAATCA). Use a guide covering that region. It must start and finish on complete codon boundaries, with its exact expected coding length documented. Do not use an unrelated fragment or assume a fixed barcode length establishes the frame.
  • Remove laboratory primers, primer tails, tags, adapters and flanking non-COI sequence. Use the known primer positions and coding annotation to define the interval; do not remove genuine COI bases solely because a short motif resembles a primer. The guide must contain only the intended biological coding region.
  • Save one nucleotide sequence in a plain FASTA file: one > header followed by ungapped A/C/G/T DNA, without N or other ambiguity codes. Keep it in the coding orientation. Its length must be divisible by three, and translation with the correct genetic code must contain no internal stop codons.
  • Do not add or delete arbitrary bases to make the length divisible by three. Resolve partial codons or incomplete mitochondrial stop annotations using the source annotation and a validated preparation, not automatic padding. A genuine terminal stop must agree with the annotated complete CDS; a barcode fragment does not need a start or terminal stop codon.

For the usual insect mitochondrial COI analysis, use genetic code 5. Confirm the correct code for other organisms. If you cannot verify the interval or its reading frame, obtain a prepared reference from the maintainer before proceeding.

What happens, step by step

  1. Export. Reads whose classification includes the taxon with confidence ≥ 0.8 are exported from the chosen samples (cleaned_TAXON_DATE.fasta).
  2. One specimen, one taxon. Reads are grouped by barcode folder + forward tag (one specimen). Within each group, only the taxon with the most reads is kept; all tied taxa are kept. Example: 37 reads Tipula tipula, 10 T. spectra, 2 T. nigris → the 37 T. tipula reads continue. Counts are added across reverse tags. The table extraction_by_barcode_primer_taxon.tsv records every decision.
  3. Consensus sequences. Within each barcode + forward tag + taxon group, reads that are at least 97% identical are combined into a consensus (VSEARCH). A group can give several consensuses when it holds distinct sequences.
  4. References. BOLD or NCBI records of the taxon are selected, whole-genome records removed, lengths outside 500–2,000 nt removed, and records of the same species that are at least 98% identical are combined. Different species are never combined.
  5. Protein check. Each consensus must translate (genetic code 5, invertebrate mitochondrial) into at least 200 amino acids without a stop codon in one of its six reading frames. This removes many NUMTs (nuclear copies of COI) and other non-coding sequences, but not all.
  6. Alignment. kc-align (with a guide) or MAFFT. kc-align may reject sequences with frameshifts or stop codons; *.kcalign_selection.tsv lists them.
  7. Trimming. ClipKIT removes alignment columns that are gaps in 90% or more of the sequences (gappy mode).
  8. Tree and figure. IQ-TREE chooses a substitution model and estimates a maximum-likelihood tree, without bootstrap support. Baltic draws it, rooted at the midpoint.

Reads without an assigned forward tag are grouped per barcode under the tag name none. Such a group can mix specimens; treat its consensuses with caution.

D. Technical reference

Clustering

VSEARCH --cluster_fast --iddef 2 --strand both, identity 0.97 for local reads (per barcode + forward tag + taxon) and 0.98 for references (per species label). Consensus sequences come from --consout; seed headers are restored.

Protein check (--min-aa)

SeqKit translates every consensus in all six frames with --translation-table (default 5). A sequence passes when one frame has at least --min-aa (default 200) consecutive amino acids without a stop (*) or unknown (X) residue. translation_lengths.tsv lists, per frame, the translation length and the longest stop-free stretch. 200 amino acids are 600 nt, and the primer-trimmed barcode region is about 658 nt, so a consensus passes only when nearly all of it is one uninterrupted reading frame: most frameshifts and internal stop codons make it fail.

Alignment

MAFFT (default): mafft --retree 2 --maxiterate 0 --adjustdirectionaccurately (FFT-NS-2) with MAFFT's default gap penalties. Sequences MAFFT reverse-complemented are recorded in alignment_orientation.tsv.

kc-align: mixed mode with the guide, genetic code --translation-table. The guide itself is not a tip. Two local helpers (kcalign_cli.py, kcalign_parallel.py) fix thread handling and a crash when kc-align rejects a read in the installed version; the biological checks are unchanged. kc-align and its fallback aligners (Kalign, MAFFT) must be installed.

Trimming

clipkit ALIGNMENT -m gappy -s nt: removes columns with a gap fraction ≥ 0.9. Columns are removed from all sequences together; single sequences are never shortened individually. The untrimmed alignment is kept.

Tree and figure

iqtree -m MFP --seed 666 on the trimmed alignment, no bootstrap. At least four sequences must remain. The figure is midpoint-rooted with Baltic; tip labels are taxon | read ID | folder | forward tag for local consensuses, organism | accession for NCBI and species | process ID for BOLD references.

Resume rules

checkpoints.json records, for each step, its output checksums, its inputs (size and modification time) and its settings. With --resume a step is reused only if all three match. parameters.json holds the original options, resume_parameters.json those of the latest resume.

Interpreting the grouped extraction table

Local extraction first keeps all requested reads in cleaned_TAXON_DATE.fasta. The audit table extraction_by_barcode_primer_taxon.tsv has columns barcode, forward_primer, reverse_primer, taxonomic_identification, read_count and kept_for_module2 (true/false). Counts are split by reverse primer, but selection sums each taxonomic label across reverse primers within each barcode + forward primer. Every label tied for the largest total survives. All reads with any of those labels are retained regardless of reverse primer or contamination flag; other labels are excluded from downstream analyses. Selection uses only the requested taxon's extracted reads, not reads outside the extraction. none, unknown and combined primer annotations remain exact distinct forward-primer values, including in unclassified when requested. none means no forward tag was assigned (status ambiguous, too_many_errors, truncated or primer_not_found in Module 1); such a group can mix specimens.

The assumption is one insect individual per barcode + forward primer, whose DNA should dominate. The most abundant label need not exceed 50% and is not proof of identity or absence of contamination. For example, barcode15/bc1009 with Tipula tipula (37), Tipula spectra (10) and Tipula nigris (2) retains the 37 Tipula tipula reads. cleaned_TAXON_DATE.dominant.fasta contains the retained original reads; the original extraction and every audit-table row remain available.

Counts represent cleaned reads, including separate adapter-split fragments, not distinct raw reads or final tree tips. Reverse-primer annotations in a cluster header describe its seed; contributing reads may have different reverse primers.

Retained local reads still cluster at 97% within each barcode/forward-primer individual: a broad genus or higher-rank assignment can hide multiple species, so all reads with that label must not automatically form one consensus. BOLD extraction retains species-identified records only; BOLD/NCBI clustering is restricted to the same header taxon label to preserve species positions in the tree. Local and reference clusters are always separate.

Local clustering uses --id 0.97 (.vsearch97.fasta); references use --id 0.98 (.vsearch98.fasta).

The shared coi_refs/ folder

coi_refs/ contains externally supplied trusted coding-reference FASTAs for --kcalign-reference, such as MT782148_cullicoides.fasta, MZ608358_Sciaridae_sp.fasta and SATIP962-10_Nigrotipula_nigra.fasta. These are alignment guides, not extracted local reads or automatic outputs of the run folder. The guide needs one ungapped, in-frame A/C/G/T coding sequence under the chosen genetic code. The adapter removes its synthetic guide entry from the final alignment.

BOLD reference extraction retains named species identifications only; genus-only, missing and provisional (sp., cf., aff.) identifications are excluded.

Review before interpreting the tree

The user must check *.clipkit.aln.fasta after ClipKIT, for example in UGENE. The pipeline does not pause before IQ-TREE; its first tree is a draft pending this review. Quickly explore *.figure.midpoint.nwk in Peartree. The user decides which local reads/consensuses and reference species/records are appropriate. Keep originals, document changes and re-estimate the tree after changing the sequence set or alignment. See the complete review instructions.

For a field-by-field explanation of local read headers and tracing a sequence through counts, clusters and alignments, see Reading the local read headers. After reviewing and editing the alignment, estimate the final tree with bootstrap support; the initial automatic pipeline run remains without bootstrap. The guide provides a separate final IQ-TREE example and links to the Baltic gallery for Python figures.

Run from the project folder. The first command writes the list of files; the second packs them. Nothing is analysed again.

import json, sys

    print(files['clean_reads']['path'])

Every path in share.list must start with data/; if one starts with /, the analysis was made outside the project folder and the collaborator would need the same absolute path. Add data/postprocessing/coi_refs/*.fasta to the tar command to include your COI guides. The reads are already compressed, so expect an archive of roughly the same size as the files.

Glossary

TermMeaning
AlignmentSequences written one below the other, with gaps (-) inserted so that corresponding positions line up in columns.
Barcode folderA folder such as barcode01 written by MinKNOW: all reads carrying one ONT native barcode, i.e. one pool of PCR products. Here also called a sample.
Bootstrap supportA number on a tree branch (0–100) saying how consistently the data support that branch. Module 2's draft tree has none; add it for the final tree.
BOLDBarcode of Life Data System, a database of DNA barcodes from identified specimens.
ChimeraAn artificial read made of two molecules joined together. fastplong splits reads at internal adapters.
ClipKITProgram that removes alignment columns that are mostly gaps.
COICytochrome c oxidase subunit I, the mitochondrial gene used as the animal DNA barcode. COI-5P is the barcode region at its 5' end.
ConfidenceSINTAX's support (0–1) for a name at one rank. Ranks with confidence ≥ 0.8 are accepted.
Consensus sequenceOne sequence summarising a group of similar reads: at each position, the most common base.
Contamination flagWarning that a taxon was found in ≥ 80% of the barcode folders. Not proof of contamination.
Core (primer core)The part of a primer that binds the COI gene, without the tag.
cutadaptProgram that finds primer sequences in reads and cuts them off.
Degenerate baseA letter standing for several bases, used in primers: R = A/G, K = G/T, M = A/C, W = A/T, Y = C/T, N = any.
Edit distance / errorNumber of substitutions, insertions and deletions needed to turn one sequence into another.
fastplongProgram that filters long reads by quality and length and removes adapters.
FASTA / FASTQText formats for sequences. FASTA: a > header line then the sequence. FASTQ: also a quality score per base. .gz means compressed.
Forward / reverse tagThe 16-base label at the start of a tagged primer. The forward tag (bc1001–bc1096) identifies the specimen within a pool.
IQ-TREEProgram that estimates a maximum-likelihood phylogenetic tree.
kc-alignAligner that aligns protein-coding DNA codon by codon, guided by one trusted sequence.
MAFFTGeneral-purpose sequence aligner.
MIDORIDatabase of reference mitochondrial sequences with taxonomy, used by SINTAX.
Midpoint rootingPlacing the tree's root halfway along its longest path. A drawing choice, not the true ancestor.
NUMTA nuclear copy of mitochondrial DNA. It can look like COI but evolves differently and misleads trees.
ONTOxford Nanopore Technologies, the sequencing platform. Its reads contain more insertion/deletion errors than short-read platforms.
Reading frame / stop codonProtein-coding DNA is read in triplets (codons); a stop codon ends the protein. A frameshift or premature stop suggests an error, a pseudogene or another marker.
SINTAXClassification method (in VSEARCH) that assigns each read a taxonomy with a confidence per rank.
Tag blockThe first 21 bases of each tagged primer: the GGTAG spacer plus the 16-base tag.
TaxidNCBI's number for a taxon, e.g. the _12345 at the end of a MIDORI name.
UGENEDesktop program to view and edit alignments.
VSEARCHProgram used here for classification (SINTAX) and for clustering reads into consensus sequences.
