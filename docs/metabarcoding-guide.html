A practical guide to your sequences

From raw Nanopore reads to taxonomic tables and a phylogenetic tree. Follow one step at a time, using the menu to return to the process you need.

New computer?Set up Ubuntu and Conda first.Raw reads ready?Start Read processing: cleaning and assignment.Analysis complete?Start Postprocessing: phylogenetics.Interrupted run?Resume from completed work.

This is an offline handbook. Double-click this HTML file in Windows to open it in Edge, Firefox or Chrome. No server, build, account or internet connection is needed to read it. Installation, external reference downloads and linked websites need internet.

The browser prepares instructions; Ubuntu runs the analysis. Copy a command, paste it into the named terminal, then press Enter. This page cannot execute local programs or inspect your files. A copied command is not a completed analysis.

Keep the project’s code/, config/, sample data and metadata together. This guide is based on the current scripts, reviewed 29 October 2026. Biological results and existing environments were not changed when preparing it.

  1. Read processing
    Raw reads → primer tracking + cleaning → SINTAX → tables and notebooks
  2. Postprocessing
    Taxon export + references → 98% consensus clustering → optional translation screen → alignment → ClipKIT → IQ-TREE → Baltic figure
Computer setup

1 · Enable Linux in Windows 11

WSL is the Windows Subsystem for Linux. It lets you run Ubuntu and this pipeline alongside Windows. These instructions target an Intel/AMD Windows 11 computer (Linux x86_64).

  1. Open Start, search for PowerShell, right-click it and select Run as administrator.
  2. Run the command below. Restart Windows when requested.
Windows · Administrator PowerShell
wsl --install -d Ubuntu

Open Ubuntu from Start. Finish its first-time setup by choosing a Linux username and password. No characters appear while typing the password; this is normal. The Linux account is separate from your Windows account.

Windows · PowerShell
wsl --list --verbose

Look for Ubuntu with VERSION 2. If it shows 1, use wsl --set-version Ubuntu 2 in PowerShell. Use the exact distribution name shown in the list. If installation reports disabled virtualisation, follow your computer manufacturer’s instructions to enable it in UEFI/BIOS.

Setup reference: Microsoft: install WSL · WSL commands.

Use a Linux Conda installation inside WSL. If conda --version already works in Ubuntu, use that installation and skip installing another. Otherwise, open the official Miniconda installer directory and download Miniconda3-latest-Linux-x86_64.sh with your Windows browser, saving it in Downloads. Choose the Linux .sh installer.

These commands and the environment recipe target x86_64. For ARM (aarch64), check package availability before continuing.

Open Windows Downloads from Ubuntu

Windows C:\ is mounted at /mnt/c/. Replace USERNAME with your Windows account folder name, which may differ from your Ubuntu username. Windows C:\Users\USERNAME\Downloads is accessible with:

Run ls /mnt/c/Users to find the account folder. Ubuntu's ~ is your Linux home, not Windows Documents. Use forward slashes and quote paths if the paths or file names contain spaces.

Read processing

1A · Clean reads and assign taxonomy

Detailed steps for run_metabarcoding_pipeline.sh: Inputs and sample folder layout · Settings and configuration · Preview, run and follow progress · Prepare the SINTAX database once · Clean and combine FASTQ reads · Classify cleaned reads with SINTAX · Reuse, interrupted runs and regeneration · Output checklist and troubleshooting. Search the left menu by script name, input, output filename, setting or error message.

Input: raw *.fastq.gz files. Output: cleaned reads and SINTAX taxonomic labels. Existing completed outputs are reused by default.

Review configuration first:

Ubuntu · Bash
cat config/pipeline.env

The current defaults use fastplong quality filtering, adapter trimming and read lengths of 300–1,900 nt. SINTAX considers 300–2,000 nt, both strands, a fixed seed of 666 and the configured MIDORI reference. These are protocol-specific settings, not universal thresholds.

Preview one sample without running the analysis:

Ubuntu · Bash
bash code/run_metabarcoding_pipeline.sh --dry-run data/mergedseq5/barcode01

Then process that sample, or process the whole selected range:

Ubuntu · Bash
bash code/run_metabarcoding_pipeline.sh data/mergedseq5/barcode01
Ubuntu · Bash
bash code/run_metabarcoding_pipeline.sh mergedseq5

For a raw unclassified folder, the cleaning/classification script also accepts:

Ubuntu · Bash
bash code/run_metabarcoding_pipeline.sh data/mergedseq5/unclassified

What happens: the reference is decompressed only when needed; a missing UDB is built once. Cleaned reads are combined into filtered/asinput.fastq.gz. Results go to data/sintax/FOLDER/FOLDER_sintaxSP.tsv. fastplong HTML reports are in the sample’s filtered/ folder.

Use a unique output root for a different sequencing dataset: the sample basename determines SINTAX output names. For example, set SINTAX_OUTPUT_ROOT=data/sintax_newdataset before the command and configure subsequent analysis accordingly. Do not use FORCE=1 casually; it requests regeneration.

The classifier’s configured cutoff is 1; the post-classification analysis independently uses the recorded per-rank confidence at ≥0.80. Read processing does not generate consensus sequences or perform the protein-length screen.

1A.1 · Inputs and sample folder layout

Merge pass/fail reads before analysis

For layouts such as mergedseq5/barcode01/pass/*.fastq.gz and mergedseq5/barcode01/fail/*.fastq.gz, run this once before analysis. It also handles unclassified, passed/failed, fastq_pass/fastq_fail and the alternative layout mergedseq5/pass/barcode01/.

Ubuntu · Bash
python code/merge_pass_fail.py mergedseq5 --dry-run
python code/merge_pass_fail.py mergedseq5

The helper writes pass_fail_merged.fastq.gz directly inside each sample, preserving the original files and recording their paths/sizes/modification times. It accepts gzip FASTQ only. Repeating unchanged merges reuses the result. Existing other direct raw FASTQs or previous analyses cause an error to prevent double counting or stale results; changed inputs need a fresh dataset. Read processing applies its own quality filtering to the combined passed and failed reads. Already-flat sample folders need no merge.

Run everything with the parent folder

Any dataset name works: sequencing2 is as valid as mergedseq5. A bare name resolves under data/; full paths can point elsewhere. No dataset name needs to begin with merged. For example:

Ubuntu · Bash
python code/merge_pass_fail.py sequencing2 --dry-run
python code/merge_pass_fail.py sequencing2
python code/read_processing.py sequencing2 --output-dir data/read_processing/sequencing2_run01
python code/postprocess_sintax.py sequencing2 --bold --taxon Tipulidae --analysis-dir data/read_processing/sequencing2_run01/analysis --output-dir data/postprocessing/Tipulidae_sequencing2_run01 --threads 8

Read-processing defaults to data/sintax/sequencing2/ for this dataset's classification files. Barcode and unclassified names stay unchanged inside the parent. Folder names do not determine biological metadata: supply a plate map and configured adapter/primer FASTAs appropriate to the experiment.

A bare mergedseq5 resolves to data/mergedseq5; full paths work too (quote spaces). The launcher discovers nonempty barcodeNN and unclassified folders. It runs cleaning, SINTAX, primer detection, best-hit parsing and every analysis notebook:

Ubuntu · Bash
conda activate taxonomy
python code/read_processing.py mergedseq5 --dry-run
python code/read_processing.py mergedseq5 --output-dir data/read_processing/mergedseq5_run01
python code/postprocess_sintax.py mergedseq5 --bold --taxon Tipulidae --analysis-dir data/read_processing/mergedseq5_run01/analysis --output-dir data/postprocessing/Tipulidae_run01 --threads 8

Prepare raw reads, adapter/primer FASTAs, the plate map and reference databases first. Read processing writes analysis/, primertrack/ and executed notebooks under its new run directory; omit --output-dir for a timestamped run. Classification defaults to data/sintax/DATASET/, keeping barcode outputs from separate datasets apart. Use --sintax-root PATH for a custom location; explicitly select --sintax-root data/sintax for legacy outputs directly under that root. Supply the correct --plate-map for your experiment. For an interrupted launcher, use a new run output directory; completed cleaning/classification/primer-hit files are reused.

Unclassified: its read-level analysis is included with PCR_plate=unassigned. It contributes neither a plate nor taxon presence to cross-plate contamination prevalence. Flags inferred from the mapped barcode plates can still annotate its reads. With no mapped plates, no cross-plate flags are inferred. Missing primer-hit records remain unknown. Postprocessing includes only folders in the completed analysis, so older analyses need regeneration to add previously omitted unclassified.

run_metabarcoding_pipeline.sh accepts one or more dataset parents or individual sample folders. It discovers immediate barcodeNN and unclassified folders, skips empty/non-sample folders, and rejects duplicate sample names across parents. Each folder basename, such as barcode01 or unclassified, becomes its output identifier.

Ubuntu · Bash

1A.4 · Prepare the SINTAX database once

Download MIDORI and place it in the project

Open the official MIDORI download page. Follow Previous releases to Zenodo and select GB272 (June 2026) for the current configuration. Select SINTAX → UNIQ → NUC_SP → CO1, download the containing archive, and extract the matching reference file. Preserve its taxonomy headers. For a newer release, keep its real filename and update the configuration.

Ubuntu · Bash
mkdir -p data/sintax

Place MIDORI2_UNIQ_NUC_SP_GB272_CO1_SINTAX.fasta or its .fasta.gz sibling in data/sintax/. Unpack outer ZIP/TAR archives first. Manual gzip decompression is optional: when the UDB and plain FASTA are absent, Read processing decompresses the gzip FASTA and builds the UDB. To decompress manually while preserving the download:

Ubuntu · Bash
gzip -dk data/sintax/MIDORI2_UNIQ_NUC_SP_GB272_CO1_SINTAX.fasta.gz

SINTAX_REFERENCE always names the plain .fasta path, and SINTAX_DB names the matching .udb, as configured in config/pipeline.env. The complete instructions are in data/sintax/README.md. Database downloads and generated UDB files stay outside Git.

1A.6 · Classify cleaned reads with SINTAX

Input: the sample’s filtered/asinput.fastq.gz and the configured UDB. Process: VSEARCH SINTAX with --sintax_random, both strands, cutoff 1, seed 666, eight threads and length bounds 300–2,000 nt by default.

The classifier writes to a temporary TSV in the target output folder. The final TSV is published after VSEARCH succeeds. Temporary classifier output is removed on ordinary failure/exit; an abrupt system shutdown may leave temporary files, which are not completed results.

Field in the tab-delimited SINTAX fileMeaning
1 · Query ID/headerIdentity of the cleaned sequence being classified.
2 · Candidate taxonomyTaxonomic ranks and bootstrap confidences in parentheses.
3 · StrandClassifier strand information.
4 · Accepted taxonomyLabels passing the classifier cutoff. This may differ from the notebook’s independently recomputed ≥0.80 assignment.

Raw SINTAX TSVs are machine outputs without a column-header row; the later analysis tables do have column names. Do not add a header to a classifier file manually.

Ubuntu · Bash
head -n 3 data/sintax/mergedseq5/barcode01/barcode01_sintaxSP.tsv

Output naming is SINTAX_OUTPUT_ROOT/SAMPLE/SAMPLE_SUFFIX.tsv. For the defaults: data/sintax/mergedseq5/barcode01/barcode01_sintaxSP.tsv. Read IDs are needed for the primer joins, cleaned-read exports and later analyses.

This script stops after classification. It does not calculate contamination flags, run notebooks, detect primers, translate reads or infer trees. Continue with primer tracking and post-classification notebooks.

1A.7 · Reuse, interrupted runs and regeneration

This shell script has no --resume option. Run the same command again to use its existing-file checks. This differs from Postprocessing’s hash-based checkpoints.

Check, in execution orderDefault behavior
Final SINTAX TSV existsSkip the entire sample, including cleaning. The check is existence, not contents or parameter equivalence; even an empty final TSV is treated as existing.
No final TSV; combined cleaned FASTQ is nonemptyReuse it directly for classification.
Cleaning needed; filtering.done existsSkip the per-file filtering loop.
Filtering loop reached; per-file cleaned output is nonemptySkip that individual raw input.
Combining reached; combined.done and nonempty combined FASTQ existReuse the combined file.
Database is nonemptyReuse it without checking changed reference contents.

After an interrupted run, inspect logs and partial outputs before retrying. A nonempty per-file output alone is not proof of a complete file; the script does not validate its checksum. Do not fabricate completion markers to make a run pass.

Intentional regeneration

FORCE_SINTAX=1 reruns classification while allowing cleaned reads to be reused. It replaces the final SINTAX TSV on success; any completed downstream analysis then needs regeneration because its manifest is stale.

Use these only when intentionally replacing outputs, after preserving anything needed for comparison. For experiments with different data or settings, a separate sample/output location is easier to audit.

Confidence ≥0.80: each rank is checked independently. The lowest qualifying rank supplies the trusted assignment. SINTAX values are bootstrap confidences, not calibrated probabilities. Species counts include queries whose species confidence passes; candidate species with no passing queries can remain with zero confident count.

Contamination screen: a taxon/rank is flagged if it appears confidently in ≥80% of distinct PCR-plate codes among analysed samples. Missing classifier outputs are excluded from the denominator; several barcodes on one plate count as one plate. A flag is evidence to review, not proof of contamination. The read-level flag applies to the lowest trusted taxon.

Read counts: adapter-split fragments count as separate cleaned queries; raw_read_count counts distinct original parents. median_confidence uses passing species queries. Canonical primer columns are forward_PCR_primer / reverse_PCR_primer, or aggregated forward_primers_detected / reverse_primers_detected.

Postprocessing

2C · Build 98% cluster consensus sequences

This happens automatically after extraction and reference preparation. Local sequences and external references never enter the same cluster.

DatasetGrouping before VSEARCH
Local cleaned readsOne group for each exact barcode/folder + forward primer + reverse primer + trusted taxonomic label tuple in the FASTA header.
NCBI or BOLD referencesAll eligible reference sequences together, clustered separately from local reads.

VSEARCH uses --cluster_fast --id 0.98 --iddef 2 --strand both --qmask none --consout. The downstream representatives are consensus sequences, not the original centroid reads. Different local groups stay separate even if their DNA is identical.

Consensus headers retain the cluster seed’s read ID or accession and annotations. They identify the seed and cluster provenance; the consensus has not received a fresh SINTAX assignment. UC membership files trace the contributors.

Look for *.vsearch98.fasta, vsearch_local_groups.tsv, vsearch_local_memberships.tsv, reference *.vsearch98.uc and clustering_counts.tsv. The combined input is combined_TAXON_DATE.fasta.

Postprocessing

2D · Translation screening or nuclear loci

By default, SeqKit translates each combined consensus in all six frames using genetic code 5 (invertebrate mitochondrial). At least one frame must contain ≥200 consecutive amino acids, split at stops and unknown residues. --min-aa changes the threshold; --translation-table changes the code.

Accepted nucleotide sequences go to combined_TAXON_nonumt_DATE.fasta, with frame measurements in translation_lengths.tsv. “nonumt” is a filename convention: passing this screen does not prove that a sequence is free of NUMTs.

For nuclear/noncoding loci, use default MAFFT and --skip-translation. All consensuses then go to combined_TAXON_selected_DATE.fasta, with no six-frame file or translation-selection table. Both the local assignments and external database must be appropriate for that marker.

--download still searches COI. BOLD mode includes every matching marker. Use an appropriate nuclear reference dataset rather than treating the skip flag as a marker-selection option. kc-align still applies its own coding-sequence checks when the earlier translation screen is skipped.

At least four retained sequences are needed for phylogeny. The reference 500–2,000 nt filter remains active in all modes.

Postprocessing

2E · Align with MAFFT or kc-align

MAFFT: default

Without an aligner flag, the module uses FFT-NS-2 nucleotide alignment with --retree 2 --maxiterate 0 --adjustdirectionaccurately --op 20 --ep 18. Tracking headers are restored after strand adjustment. This is the general choice for nuclear/noncoding loci.

kc-align: coding sequences with a trusted reference

Ubuntu · Bash
python code/postprocess_sintax.py --bold --taxon Tipulidae --folders barcode{01..21} --analysis-dir data/sintax_analysis/mergedseq5_20261021 --output-dir data/postprocessing/Tipulidae_bold_kcalign_run01 --kcalign --kcalign-reference data/postprocessing/coi_refs/SATIP962-10_Nigrotipula_nigra.fasta --translation-table 5 --threads 6

You must provide a trusted reference. Its FASTA must have one >header and one ungapped A/C/G/T coding sequence. Length must be divisible by three, and the first base must be the first nucleotide of the first codon in the selected coding region. No internal stops are allowed under the chosen code. Verify the frame biologically; trimming arbitrary bases to make the length divisible by three is not sufficient.

Mixed mode receives the same selected nucleotide consensus file as MAFFT. The local adapter handles installed entry-point and parallel-rejection bugs without modifying Conda packages. Threads must be 1 or a positive multiple of 3, passed unchanged from the module’s setting. A six-thread setting budgets up to two concurrent per-read workers.

--keep is a switch in the installed tool. The pipeline saves PREFIX.pre_align.aa.fasta and PREFIX.aln.fasta; the first is an amino-acid audit file, the second is the nucleotide alignment. The guide reference is not added as an extra tree tip. Rejected input IDs are listed in PREFIX.kcalign_selection.tsv. At least four aligned consensuses must remain.

Postprocessing

2F · Trim columns with ClipKIT

This automatic step follows both alignment programs, including runs that skip translation screening.

Underlying command · PREFIX is a placeholder
clipkit PREFIX.aln.fasta -m smart-gap -s nt -if fasta -of fasta -o PREFIX.clipkit.aln.fasta

Smart-gap chooses a gap threshold and removes gappy alignment columns. It does not independently delete every gap in every sequence, and gaps may remain. The original alignment is preserved.

The sequence set and headers must remain unchanged and the trimmed alignment must be nonempty and rectangular. IQ-TREE receives PREFIX.clipkit.aln.fasta. Check clipkit.stdout.log and clipkit.complete.json for the report and resume proof.

Postprocessing

2G · Infer the tree and open the figure

IQ-TREE performs automatic model selection (-m MFP), with seed 666 and the requested thread count. Bootstrap replicates are disabled to reduce runtime: this produces a maximum-likelihood tree without bootstrap support values. The bootstrap command is commented in the source, and --bootstrap-method is no longer an accepted option. It uses the ClipKIT-pruned nucleotide alignment. On the first resume under this setting, the saved alignment and trimming are reused while the tree and figure are rebuilt; old tree outputs and checkpoints are archived. Stop any existing job using that output directory before resuming.

Baltic draws a midpoint-rooted divergence tree. Branch lengths are substitutions per site, not calendar time. Existing bootstrap labels follow their corresponding branches. If the main tree lacks support labels but the consensus tree has them, the supported consensus topology is used.

PREFIX.figure.svgOpen in a browser and zoom. Tip labels may require a large view.

PREFIX.treefile / .iqtreeTree topology and the model/bootstrap analysis report.
