# Bash Metabarcoding Pipeline

This repository contains a shell-based metabarcoding workflow plus notebooks for
parsing Kraken2 and primer/UMI tracking outputs.

For the current end-to-end run order from fastplong onwards, including
single-barcode/all-barcode commands and table-column documentation pointers,
see:

```text
docs/pipeline_from_fastplong_onwards.md
```

## Main Commands

Edit defaults in:

```bash
config/pipeline.env
```

Run one barcode folder:

```bash
conda activate saproxdna
bash code/run_metabarcoding_pipeline.sh data/mergedseq6/barcode01
```

Run several folders, with two barcode folders active at a time:

```bash
MAX_JOBS=2 bash code/run_metabarcoding_pipeline.sh \
  data/mergedseq6/barcode01 \
  data/mergedseq6/barcode02 \
  data/mergedseq6/barcode03
```

Rerun everything:

```bash
FORCE=1 bash code/run_metabarcoding_pipeline.sh data/mergedseq6/barcode01
```

Rerun only Kraken2 and the Kraken read map, keeping filtering and
amplicon_sorter outputs:

```bash
FORCE_KRAKEN=1 bash code/run_metabarcoding_pipeline.sh data/mergedseq6/barcode01
```

Run primer/UMI tracking:

```bash
bash code/run_primer_umi_tracking.sh data/mergedseq5
```

data/
  mergedseq5/

## Pipeline Outputs Per Barcode

For each barcode folder, the current pipeline writes:

```text
data/mergedseqX/barcodeYY/
  filtered/
    *_filtered.fastq.gz
    *_report.html
    asinput.fastq.gz
    filtering.done
    combined.done
    amplicon_sorter.done
    kraken2.done
    consensusfile.fasta
    results.csv
    logs/
      *.log
      amplicon_sorter.stdout.log
      amplicon_sorter.stderr.log
      amplicon_sorter.log
      kraken2.log
    combined/
      amplicon_sorter_read_map.tsv
      results.txt
      asinput_*_*.fasta
      asinput_*_alignment.fasta
      asinput_*_unique.fasta
      asinput_consensussequences.fasta
      asinput_nogroup_unique.fasta
      kraken2_combined_input.fasta
      kraken2_combined_input.read_map.tsv
      kraken2_combined_input.fasta.kraken
      kraken2_combined_input.fasta.report
```

`filtered/logs/amplicon_sorter.stdout.log` preserves the terminal output from
amplicon_sorter. `filtered/logs/amplicon_sorter.stderr.log` preserves stderr.
`filtered/logs/amplicon_sorter.log` is the combined compatibility log used by
the pipeline checks.

The pipeline uses `code/amplicon_sorter_mod.py`, a local copy of
`code/amplicon_sorter.py` that writes `amplicon_sorter_read_map.tsv` while it
loads reads. amplicon_sorter itself writes numeric FASTA headers for individual
reads. These numbers are internal amplicon_sorter indexes after length
filtering, not ONT read UUIDs. The file `filtered/asinput.fastq.gz` is
the combined filtered raw-read input to amplicon_sorter. The file
`kraken2_combined_input.read_map.tsv` combines the amplicon_sorter map with the
Kraken input FASTA and links:

```text
kraken_read_id -> amplicon_sorter_read_number -> ont_read_id
```

Existing amplicon_sorter outputs that do not contain
`amplicon_sorter_read_map.tsv` need to be rerun with the modified script before
the Kraken read map can be generated by the current pipeline.

Consensus records do not have one ONT read ID. They are marked as
`record_type = consensus` and keep their amplicon_sorter group name and sequence
length.

## Amplicon Sorter Length Check

`code/length_check_amplicon_sorter.sh` summarizes sequence lengths for every
non-alignment amplicon_sorter FASTA file across all barcodes in a merged-sequence
folder.

Run this after amplicon_sorter and Kraken2 have produced:

```text
data/mergedseq5/barcodeXX/filtered/combined/asinput_*_*.fasta
data/mergedseq5/barcodeXX/filtered/combined/kraken2_combined_input.read_map.tsv
data/mergedseq5/barcodeXX/filtered/combined/kraken2_combined_input.fasta.kraken
data/mergedseq5/barcodeXX/filtered/combined/kraken2_combined_input.fasta.report
```

The full `code/run_metabarcoding_pipeline.sh` step already includes
amplicon_sorter, Kraken2, and the Kraken read map, so the length check can be
run after that pipeline finishes.

Run with defaults:

```bash
code/length_check_amplicon_sorter.sh
```

Default input folder:

```text
data/mergedseq5
```

Default output table:

```text
data/mergedseq5/mergedseq5_amplicon_sorter_length_check.tsv
```

Run with explicit input and output paths:

```bash
code/length_check_amplicon_sorter.sh \
  data/mergedseq5 \
  data/mergedseq5/mergedseq5_amplicon_sorter_length_check.tsv
```

The script excludes files matching:

```text
*alignment*fasta
```

Kraken2 taxid assignment is added from the per-barcode combined Kraken files:

- grouped files such as `asinput_1_0.fasta` are linked to the Kraken2 taxid of the corresponding consensus sequence using `kraken2_combined_input.read_map.tsv`;
- unique files such as `asinput_0_unique.fasta` and `asinput_nogroup_unique.fasta` summarize all individual Kraken records whose `amplicon_sorter_file` is that unique FASTA file.
- taxon names are taken from `kraken2_combined_input.fasta.report`.

The output is tab-delimited and contains one row per FASTA file.

| Column | Meaning |
|---|---|
| `barcode` | Barcode folder containing the FASTA file. |
| `asinput_file` | FASTA filename, for example `asinput_1_0.fasta`, `asinput_0_unique.fasta`, or `asinput_nogroup_unique.fasta`. |
| `cluster_group` | Parsed cluster/group label without the `asinput_` prefix or `.fasta` suffix. |
| `cluster_number` | First parsed value after `asinput_`. For `asinput_nogroup_unique.fasta`, this is `nogroup`. |
| `group_number` | Second parsed value after `asinput_`. For unique files, this is `unique`. |
| `sequence_count` | Number of FASTA records in the file. |
| `average_length` | Mean sequence length in bases. |
| `length_standard_deviation` | Sample standard deviation of sequence lengths in bases. Files with one sequence have standard deviation `0`. |
| `kraken_record_type` | Kraken record type summarized for this FASTA file: `consensus`, `unique_read`, a semicolon-separated combination if both occur, or `none` if no Kraken records were matched. |
| `kraken_record_count` | Number of Kraken records associated with this FASTA file. Grouped files usually have one consensus record; unique files can have many individual-read records. |
| `kraken_classified_count` | Number of associated Kraken records classified by Kraken2. |
| `kraken_unclassified_count` | Number of associated Kraken records unclassified by Kraken2. |
| `kraken_taxids` | Semicolon-separated Kraken taxids associated with the file. Taxid `0` means unclassified. |
| `kraken_taxon_names` | Semicolon-separated taxon names corresponding to `kraken_taxids`, in the same order. Names are taken from `kraken2_combined_input.fasta.report`. |
| `kraken_taxid_counts` | Semicolon-separated `taxid:count` pairs for the associated Kraken records. |
| `file_path` | Full path to the FASTA file used for the calculation. |

## Consensus noNUMT Amino-Acid Filter

`code/filter_consensus_noNUMT_seqkit.sh` translates amplicon_sorter consensus
sequences in all six frames and keeps translated amino-acid sequences above the
configured minimum length. This is intended as a quick consensus-level NUMT
screening aid.

Run this after amplicon_sorter has produced:

```text
data/mergedseq5/barcodeXX/filtered/combined/asinput_consensussequences.fasta
```

Run all barcodes under one parent folder:

```bash
bash code/filter_consensus_noNUMT_seqkit.sh data/mergedseq5
```

Run one barcode:

```bash
bash code/filter_consensus_noNUMT_seqkit.sh data/mergedseq5/barcode01
```

The script uses variables from `config/pipeline.env`:

| Variable | Default | Meaning |
|---|---:|---|
| `NONUMT_MIN_AA_LENGTH` | `100` | Minimum amino-acid length retained by `seqkit seq --min-len`. |
| `NONUMT_TRANSLATION_TABLE` | `5` | Genetic code table passed to `seqkit translate -T`. |
| `NONUMT_SEQKIT_THREADS` | `6` | Threads passed to `seqkit translate -j`. |
| `MAX_JOBS` | `2` | Number of barcode folders processed concurrently. |
| `FORCE` | `0` | Set to `1` to overwrite existing noNUMT outputs. |

For each input file, the output is written in the same folder. With default
settings:

```text

asinput_consensussequences_aa_noNUMT_100filter.fasta
```

```text
data/kraken_parsed/

  mergedseqX_<target>_kraken_reads_YYYYMMDD.csv

```

These notebook-generated tables are tab-delimited even though their filenames
retain the `.csv` extension. Load them with `sep='\t'` in pandas.

These parser outputs are dated and are used as later inputs. Every time
`code/kraken_parser.ipynb` creates a new `mergedseqX_all_kraken_reads_YYYYMMDD.csv`
or `mergedseqX_<target>_kraken_reads_YYYYMMDD.csv`, update the downstream code or
commands that point to those files. In particular, update the
`--insecta-kraken-reads` path used by `code/build_barcode_read_tracking_table.py`
to the newest intended `mergedseqX_insecta_kraken_reads_YYYYMMDD.csv`.

`code/kraken_parser.ipynb` expects the Kraken read map generated by the current
pipeline. It uses `ont_read_id` from `kraken2_combined_input.read_map.tsv` to
join Kraken taxonomy to primer/UMI best hits.

## Per-read Primer, Amplicon Group, and Taxid Table

`code/build_barcode_read_tracking_table.py` combines the raw-read IDs, best
forward and reverse primer/UMI hits, amplicon_sorter subgroup membership, group
consensus Kraken assignment, and individual-read Kraken assignment. It also
intersects this table with the tab-delimited Insecta output from
`kraken_parser.ipynb`. Consensus IDs select all processed reads assigned to that
amplicon_sorter group. Individual read IDs are traced through
`kraken2_combined_input.read_map.tsv` to processed ONT read IDs. For barcode01,
run:

```bash
python code/build_barcode_read_tracking_table.py \
  --barcode-dir data/mergedseq5/barcode01 \
  --primer-best-hits data/primertrack/mergedseq5_seqkit_primer_umi_best_hits_20260630.txt \
  --insecta-kraken-reads data/kraken_parsed/mergedseq5_insecta_kraken_reads_20260630.csv \
  --output data/mergedseq5/barcode01/barcode01_read_primer_group_taxid.tsv
```

If the Insecta parser output has been regenerated with a newer date, replace the
dated filename in `--insecta-kraken-reads`. Otherwise the read-tracking script
will use the older parsed Insecta table and can produce empty or incomplete
`barcodeXX_insecta_read_primer_group_taxid*` outputs for newer barcodes.

The script writes both reduced tables before compressing and removing the two
uncompressed full tables. The four final outputs are:

```text
barcode01_read_primer_group_taxid.tsv.gz
barcode01_read_primer_group_taxid_reduced.tsv
barcode01_insecta_read_primer_group_taxid.tsv.gz
barcode01_insecta_read_primer_group_taxid_reduced.tsv
```

Both reduced tables contain, in order:

```text
raw_ont_read_id
forward_patternName
reverse_patternName
group_consensus_kraken_taxid
individual_read_kraken_taxid
```

The output is a long-format TSV. Every raw FASTQ read occurs at least once. An
unsplit read has one row. If fastplong splits a raw read at an internal adapter,
the raw read can have separate `left` and `right` rows. This is necessary because
the two processed fragments can receive different amplicon groups or Kraken
assignments. Primer hits are measured on the raw read and are repeated on each
of its processed-fragment rows.

The output columns are:

| Column | Meaning |
|---|---|
| `merge_folder` | Sequencing merge/run folder, for example `mergedseq5`. |
| `barcode` | Barcode folder, for example `barcode01`. |
| `raw_ont_read_id` | Original ONT read UUID from the unfiltered raw FASTQ. This is the parent ID for split fragments. |
| `raw_fastq_file` | Raw FASTQ file containing the original read. |
| `raw_read_length` | Length of the original unfiltered read. |
| `forward_patternName` | Name of the best forward primer/UMI hit on the raw read. Blank when no forward hit was found. |
| `forward_strand` | Strand of the best forward hit (`+` or `-`). |
| `forward_start`, `forward_end` | Coordinates reported by seqkit for the best forward hit. |
| `forward_mismatch_count` | Number of mismatches in the best forward hit. |
| `forward_primer_identity` | Best forward-hit identity, from `0` to `1`. |
| `reverse_patternName` | Name of the best reverse primer/UMI hit on the raw read. Blank when no reverse hit was found. |
| `reverse_strand` | Strand of the best reverse hit (`+` or `-`). |
| `reverse_start`, `reverse_end` | Coordinates reported by seqkit for the best reverse hit. |
| `reverse_mismatch_count` | Number of mismatches in the best reverse hit. |
| `reverse_primer_identity` | Best reverse-hit identity, from `0` to `1`. |
| `entered_amplicon_sorter` | `yes` when an unsplit read or derived fragment was present in amplicon_sorter's input map; otherwise `no`. |
| `processed_read_id` | ID passed to amplicon_sorter. For split reads this is `split-by-adapter-left-<UUID>` or `split-by-adapter-right-<UUID>`. Blank when the raw read did not enter amplicon_sorter. |
| `processed_fragment` | `original`, `left`, or `right`. Blank when the read did not enter amplicon_sorter. |
| `processed_read_length` | Length after filtering, trimming, and possible adapter splitting. |
| `amplicon_sorter_group` | Exact amplicon_sorter subgroup, for example `1_0`. Blank for ungrouped reads. |
| `amplicon_sorter_group_consensus_id` | Consensus FASTA/Kraken record ID corresponding to the subgroup. |
| `group_consensus_kraken_taxid` | Kraken taxid assigned to the subgroup consensus. This taxid is propagated to every processed read in that subgroup. |
| `individual_read_kraken_input_file` | amplicon_sorter FASTA used as the individual-read Kraken input, such as `asinput_nogroup_unique.fasta` or `asinput_1_unique.fasta`. Blank when that processed read was not one of the unique records sent individually to Kraken. |
| `individual_read_kraken_taxid` | Kraken taxid assigned directly to the individual unique-read sequence, distinct from the group-consensus taxid. |

A blank taxid means no corresponding Kraken record was available. Taxid `0`
means that the corresponding record was sent to Kraken but was unclassified.
A read may have a group-consensus taxid without an individual-read taxid because
Kraken receives the group consensus plus only the unique individual sequences
selected by amplicon_sorter.

### Why the two taxid columns are separate

In the current pipeline, `group_consensus_kraken_taxid` and
`individual_read_kraken_taxid` represent mutually exclusive amplicon_sorter
outcomes:

- Reads assigned to an amplicon_sorter subgroup are represented in Kraken by
  the subgroup consensus. Its Kraken assignment is recorded in
  `group_consensus_kraken_taxid` and propagated to all reads in that subgroup.
- Records in `asinput_<number>_unique.fasta` are sequences that amplicon_sorter
  considered unique within the broader numbered group; they are not members of
  a consensus subgroup. Records in `asinput_nogroup_unique.fasta` were likewise
  not assigned to a consensus subgroup. Kraken classifies these sequences
  directly, and their assignments are recorded in
  `individual_read_kraken_taxid`.

Thus, `individual_read_kraken_taxid` is not a copy of a propagated group taxid.
It is an independent classification of an individual processed sequence. For
analysis, the two columns can be combined into one effective taxid while
retaining the original columns and a source field for provenance:

```python
tracking['taxid'] = tracking['group_consensus_kraken_taxid'].combine_first(
    tracking['individual_read_kraken_taxid']
)

tracking['taxid_source'] = 'none'
tracking.loc[
    tracking['individual_read_kraken_taxid'].notna(),
    'taxid_source',
] = 'individual_read'
tracking.loc[
    tracking['group_consensus_kraken_taxid'].notna(),
    'taxid_source',
] = 'group_consensus'
```

The original taxid columns should remain in the tracking table because a taxid
derived from a group consensus and the same taxid derived from a direct
individual-read classification have different evidential provenance.

### Reduced input for evaluation

`code/evaluate_tagtracking_taxid.ipynb` reads the reduced table:

```text
data/mergedseq5/barcode01/barcode01_read_primer_group_taxid_reduced.tsv
```

No `pyarrow` installation is required. In a barcode01 benchmark, the
uncompressed reduced TSV loaded in about 2.9 seconds, compared with about 6.6
seconds for its gzipped equivalent. The full tracking table remains compressed
for storage, while the smaller reduced table remains uncompressed for faster
interactive analysis. Regenerate the reduced file whenever the full tracking
table is regenerated.

## Sankey Diagrams for Target-Species Detections

`code/sankey_target_species_detection.ipynb` creates one Sankey/alluvial diagram
per barcode from:

```text
data/mergedseq5/barcodeXX/barcodeXX_target_species_detection.tsv
```

It writes an expanded trust-annotated table:

```text
data/mergedseq5/barcodeXX/barcodeXX_target_species_detection_trusted.tsv
```

The final notebook section also combines trusted rows across selected barcodes into:

```text
data/mergedseq5/mergedseq5_target_species_detection_trusted.tsv
```

It also writes two Sankey figures:

```text
data/mergedseq5/barcodeXX/figures/barcodeXX_target_detection_sankey.png
data/mergedseq5/barcodeXX/figures/barcodeXX_target_detection_sankey_trusted.png
```

The same notebook also reads `barcodeXX_target_species_taxids_below_50pct_forward_primers.tsv`
and applies the same Sankey and trust-coloring rules. For that filtered table,
it does not export a new expanded/trusted TSV; it only writes:

```text
data/mergedseq5/barcodeXX/figures/barcodeXX_target_species_taxids_below_50pct_forward_primers_sankey.png
data/mergedseq5/barcodeXX/figures/barcodeXX_target_species_taxids_below_50pct_forward_primers_sankey_trusted.png
```

The plotted flow is:

```text
expected_forward_primer -> detected_forward_primer -> detected_species -> target_species
```

Rules:

- The notebook uses the full `barcodeXX_target_species_detection.tsv` table, not
  the below-50% filtered target-species table.
- `expected_forward_primer` is taken directly from the row's `expected_forward`
  column. Missing or empty values are shown as `none`. Multiple
  semicolon-separated expected primers are split.
- `target_species` is taken directly from the same row's `target_species`
  column. It is not globally re-derived from the expected forward primer.
  Missing or empty values are shown as `none`.
- `detected_species` is taken from `taxid_detected_name`. Missing or empty values
  are shown as `none`.
- `detected_forward_primer` is taken from the seqkit-detected `forward_primer`
  column. Missing or empty detected forward primers are shown as `none`.
- `target_sxdcodes` and `expected_forward` are expanded together. If both
  contain the same number of semicolon-separated values, they are paired by
  position so the first SxD code remains linked to the first expected forward
  primer, and so on. If one side has one value and the other has multiple, the
  single value is repeated. Otherwise, all combinations are used and the row is
  flagged in `expansion_note`.
- If one row expands to multiple expected-primer/detected-primer/species
  combinations, the row's read count is split evenly across those combinations
  as `sankey_read_count` so total flow is conserved.
- Link weights use `taxid_primer_read_count` for detected-primer rows and
  `no_forward_primer_read_count` for no-forward-primer rows, with fallback to
  `taxid_read_count` and then `target_species_read_count`.
- Detected species and target species blocks are sorted alphabetically, with
  `none` at the end.
- Expected and detected forward-primer blocks are initialized
  alphanumerically/naturally, then refined with weighted barycentric sweeps to
  reduce path overlap/crossings. This is a layout-only operation and does not
  change link weights.
- The Sankey diagram is exploratory. It shows expected-primer, expected-target,
  detected-taxid, and detected-primer associations, not proof that the detected
  taxid is exactly the expected species.

Trust rules used for `barcodeXX_target_species_detection_trusted.tsv` and the
green trusted Sankey:

- After expansion, primer-detected rows are trusted only when
  `expected_forward_primer` and `detected_forward_primer` are the same.
- If a `target_species + expected_forward_primer` pair has multiple detected
  forward primers, only rows where the detected primer matches the expected
  primer are trusted; mismatching detected primers are not trusted.
- If a target species has multiple expected forward primers, each expanded
  expected/detected primer row is evaluated independently.
- Rows with no detected forward primer are trusted only when `target_genus` and
  `taxid_detected_genus` match and the detected species is unique to one
  `target_species + expected_forward_primer` pair in that barcode.
- Rows with no detected forward primer are not trusted when the detected species
  appears in multiple target/species expected-primer pairs.
- The trusted Sankey colors trusted links in green and untrusted links in grey.

## Temporary Files

amplicon_sorter runs in:

```text
/tmp/metabarcoding_amplicon_sorter/
```

On success, the pipeline copies usable output back to the barcode folder and
removes the temporary copy. On validation failure, the temporary copy is kept for
inspection and the log prints its path.

Temporary files that are safe to remove after checking no process is using them:

```bash
find /tmp/metabarcoding_amplicon_sorter -mindepth 1 -maxdepth 1 -type d -print
```

Remove only failed-run directories that you no longer need for inspection.

## Cleanup Candidates

Do not remove filtered reads, amplicon_sorter outputs, Kraken2 outputs, or
seqkit outputs unless you intentionally want to rerun those steps.

Common cleanup candidates are:

```text
code/__pycache__/
tmp/
```

Older parser outputs without the current dated naming scheme may also be stale,
for example undated files in `data/kraken_parsed/`. Confirm that the dated files
you need exist before deleting older parser summaries.
