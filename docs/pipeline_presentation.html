Part 1

The project

Wood-associated arthropods, one specimen at a time.

One arthropod, one well, one barcode sequence

  • Arthropods from deadwood: beetles, flies, ants, mites, spiders, springtails… Each one gets its own DNA extraction and PCR well.
  • Marker: the COI barcode region (Folmer region, ≈658 bases between primers based on LCO1490 / HCO2198). Goal: a reliable sequence and identification for every specimen.
Stress the one-specimen-per-well design. It changes the question from "which species are in this sample" to "what is this specimen, and how sure are we". Most reads in a well should belong to one species; the rest is noise or contamination that we want to see but not confuse with the specimen.

From the lab bench to read files

Each pool holds the 96 wells of one PCR plate, all of them specimens.

The negative controls of all PCRs were pooled together into barcode22. barcode23 and barcode24 hold metagenomic DNA of an ant from another study, sequenced on the same run.

Two labels travel with every read: the ONT barcode of its pool and the tags on its primers.

Each PCR product carries short tags added through the primers. Many PCR products are pooled; each pool gets an ONT native barcode before sequencing. MinKNOW sorts the reads into one folder per barcode. So the barcode tells us the pool and the tags tell us the well inside the pool.

A specimen = barcode folder + forward tag

  • Barcode folder (barcode01–barcode24): one pool of PCR products.
  • Forward tag (bc1001–bc1096): one well inside the pool.
  • Reverse tag (bc1100rc, bc1107rc, bc1122rc): recorded, used for checks.
  • Reads whose forward tag cannot be read reliably are kept as specimen none. That group can mix specimens.
This pair is the unit of everything that follows. When you see barcode07 bc1062 in a table, that is one physical specimen. The specimen called none is a bin for reads whose tag could not be trusted; never treat it as one specimen.

What one read looks like

Errors

Every read has a few errors, mostly short insertions and deletions. One read alone can look like a slightly different species.

More than one source

A well can contain other DNA: gut contents, parasites, fungi, lab contamination, reads mis-assigned from other wells.

Look-alikes

Nuclear copies of COI (NUMTs) and chimeras of two templates also get sequenced.

The coloured bar is the design of the amplicon. The tag block is a 5-base spacer GGTAG plus a 16-base tag, right next to the primer. The pipeline must find the primers, read the tags, cut everything outside the primers, and only then look at the COI part. The three boxes are the reasons we never trust a single read.

How accurate is one read?

  • Sanger: one very accurate read per reaction, but only one sequence per specimen; a mixed well gives unreadable double peaks.
  • Illumina: few errors, almost all substitutions, but reads of at most 2 × 300 bases: too short for the whole 658-base barcode in one piece.
  • PacBio HiFi: long and accurate; remaining errors are insertions and deletions in runs of one letter.
  • ONT (our run): long reads, thousands of specimens per run, about 0.9 errors per 100 bases of all three kinds: a median of 5 errors in a 658-base read, and 1–14 for 80% of reads.

ONT measured on our run: 5,398 reads from 18 large clusters, each compared with its cluster's consensus. Reads too noisy to join a cluster are not counted, so the real rate is slightly higher. Sanger, Illumina and PacBio bars are typical published values.

The ONT values are measured on our own data: 5,398 reads from 18 large clusters of run 5 (basecaller model dna_r10.4.1_e8.2_400bps_sup v5.0.0), each compared with the consensus of its cluster. Substitutions 0.50, deletions 0.25, insertions 0.16 per 100 bases. Reads that were too different to join a cluster are not counted, so the true average is a little higher. The other three bars are typical published values; they vary with chemistry and software.

The pipeline at a glance

Two modules, run at different times, by possibly different people.

Read the map left to right. Each line is one stream of data: reads in blue, tags in yellow, the MIDORI classification database in purple, BOLD or NCBI references in orange, the optional COI guide for kc-align in pink, and the grey line is the shared archive for people who only run Module 2. Squares are files you provide; pills are key outputs. The blue area is Module 1, the green area Module 2.

Two modules

ModuleWhat it doesRun itMain result
1 · Read processingFinds primers and tags, cleans reads, clusters the reads of each specimen at ≥97%, classifies every cluster with SINTAX against MIDORI, and summarises per specimen, species and pool.once per sequencing runan analysis folder
2 · PostprocessingFor one taxon: takes its clusters, keeps the main identification of each specimen, adds named reference sequences (BOLD or NCBI), checks they code for protein, aligns, trims and builds a draft tree.once per taxonan alignment and a draft tree

The pipeline never makes the final scientific decision. You decide which clusters and which reference species belong in the final tree.

Module 1 is slow and run once per sequencing run, usually by one person. Module 2 is fast and run many times, once per family or genus, often by the taxonomist who knows the group.

Part 3

Module 1 · Read processing

Primers and tags → quality filter → clusters → classification → tables.

Step 1 · Find the primers, read the tags

cutadapt

  • Searches every read for the forward and reverse primer cores (up to 5 errors in 25–26 bases).
  • Turns every read into the same direction.
  • Cuts off everything outside the primers: ONT barcode, tags, primers.

primer_tags.py

  • Takes the 21 bases next to each primer (the tag block).
  • Compares them with all 96 forward and 3 reverse tags.
  • Writes the tag and a status for every raw read to filtered/primer_tags.tsv.gz.

Trimming and tag reading are kept separate, so a tag problem never removes a good COI sequence.

Allowing more primer errors sounds generous but backfires: with 12 errors cutadapt found "primers" at random places and kept less than 2% of the bases in a test. Five errors is the setting in config/pipeline.env.

Finding a primer and a tag, base by base

A real example with the bc1001 tag. The primer core is found first; degenerate positions in the primer, written R, K and M, accept two bases each, so the read matches with no error. The 21 bases before the core are then compared with all 96 forward tag blocks. This read has one mismatch and one missing base: 2 errors from bc1001, at least 6 from any other tag, so it is assigned. Edit distance counts mismatches, insertions and deletions alike.

When is a tag trusted?

StatusMeaning
assignedWhole tag present, at most 4 errors, and at least 2 errors better than the second-best tag.
ambiguousTwo tags fit almost equally well.
too_many_errorsBest tag has more than 4 errors.
truncatedThe read starts inside the tag block, so the tag is incomplete.
primer_not_foundNo primer, so no place to look for a tag.

Why so strict?

A wrong tag puts a read into the wrong specimen and creates a false "second species" in a well. A missing tag only loses a read. We prefer to lose reads.

Settings: TAG_MAX_ERRORS=4, TAG_MIN_MARGIN=2, TAG_MIN_OBSERVED=21.

Reads without an assigned forward tag are not thrown away; they go to specimen none in their barcode folder. That keeps the read counts honest and lets you see how many reads could not be placed.

A raw read split into two pieces counts twice in later read counts. Both pieces keep the tags of the raw read.

One detail we found: left to detect adapters itself, fastplong mistook a conserved COI motif for an adapter and cut about 128 bases from every read. The settings file now names the ONT adapters explicitly to switch that off.

Step 3 · Cluster the reads of each specimen

  • VSEARCH --cluster_fast --id 0.97, separately for every barcode folder + forward tag (and none).
  • Output: filtered/clusters.fasta (one sequence per cluster) and filtered/cluster_members.tsv.gz (which read is in which cluster).
The consensus removes most random sequencing errors, because errors rarely sit at the same base in many reads. Single reads stay in the data; they may be rare true variants, contaminants, or just error-rich reads.

How VSEARCH builds the clusters

Only the COI part between the primers is clustered: barcodes, tags and primers were cut off before, and the tags already decided which specimen a read belongs to. VSEARCH sorts the reads of one specimen by length. The longest becomes the first centroid. Every next read is compared with the existing centroids, those sharing most 8-letter words first; it joins the first one it matches at 97% or more, otherwise it becomes a new centroid. The cluster and its consensus are named after the centroid's read ID.

How the consensus is made

This is real VSEARCH output on six short test reads. Each read is aligned to the centroid; in every column the most common symbol wins. One wrong base is outvoted; an extra base in one read disappears because gaps win that column; a missing base is restored. Ties go to A, C, G, T in that order, even against the centroid; this is why a two-read consensus is hardly better than a single read. The bases only the centroid has at its end are left out, so the consensus is 658 bases even when the centroid is longer.

Why 97%, and never lower

At 97%

Reads differing by sequencing errors (≈1–3%) end up together. Different species of the same genus usually differ by more than 3% in COI and stay apart.

Below 97%

Closely related species, for example two Lasius species from the same log, start to merge into one consensus. That consensus belongs to neither species.

Because clustering is done inside a specimen only, a mistake can never merge two specimens.

The 97% value is CLUSTER_IDENTITY in config/pipeline.env, with a comment telling people not to lower it. Some species pairs differ by less than 3%; those will still be separated later only if they are in different wells, which is exactly the one-specimen-per-well advantage.

Step 4 · Classify every cluster (SINTAX)

  • SINTAX compares a sequence with the MIDORI COI references by the short words they share: 8-mers.
  • 100 rounds on 32 random words; the share of rounds that agree on a name is the confidence at each rank.
  • We accept a rank when its confidence is ≥ 0.8.
  • Output: data/sintax/DATASET/barcodeNN/barcodeNN_sintaxARTH.tsv

Two MIDORI versions

Arthropoda only (default, suffix sintaxARTH): faster, but non-arthropod DNA is forced onto an arthropod name.

Full (suffix sintaxSP): also names fungi, vertebrates, bacteria; slower.

This is the slow step: roughly one second per cluster on 8 threads.

Confidence comes from bootstrap-like repeats, so 0.8 means 80 of 100 subsamples agreed. A high confidence does not mean the name is right: if the true species is missing from MIDORI, SINTAX can confidently name its closest relative.

How SINTAX names one sequence

No alignment and no % identity: only counts of shared 8-mers. When several references share equally many words, one is picked at random (--sintax_random).

Confidence says how consistently one name wins, not how similar the sequence is. A species missing from MIDORI can lend its closest relative a high confidence.

Illustration with the Lasius example: 81 of 100 rounds found a L. platythorax reference as the best match, 19 a L. niger reference, and all 100 a Lasius. So genus Lasius gets confidence 1.00 and species L. platythorax 0.81. The round counts in the middle are illustrative; the final confidences are the real ones from barcode20 bc1021.

SINTAX compared with BLASTn

Both are useful. We use SINTAX for every cluster because it is fast enough, gives a rank-by-rank answer and uses one rule for all. When a specimen matters, check its consensus with BLAST or the BOLD identification engine: the percent identity tells you whether a close reference exists at all.

The contamination screen

  • A taxon found with confidence in at least 80% of the pools is flagged contamination.
  • Typical causes: lab DNA, a very abundant specimen spilling reads into other wells, tag errors.
  • It is a warning sign, not a verdict: common deadwood species and broad ranks (Insecta) are found everywhere for good reasons.

Example from run 5

barcode20 holds two ant specimens: wells bc1021 and bc1056, with hundreds of reads each.

In the other 12 pools, Lasius turns up with 1–10 reads, mostly in wells bc1021 and bc1056: same well, wrong pool. Yet Lasius is flagged, also for the two real specimens.

Echo: reads of a specimen that turn up in another well, either the same tag in another pool (wrong ONT barcode) or another tag in the same pool (wrong tag).

The flag is computed in taxon_barcode_prevalence.tsv. When many pools are analysed together and cross-talk is common, even true specimen species can be flagged, so always look at the read counts before excluding anything.

How much was identified, per pool

Written by Module 1 as barcode_assignment_counts.png. For each pool: cleaned reads, reads with any accepted rank, and reads identified to species. A pool where few reads reach species may hold groups that are poorly covered by MIDORI, such as mites or springtails.

Part 4

Module 2 · Postprocessing

One taxon at a time: your specimens next to named species.

Eight steps from clusters to a draft tree

1 · Export the clusters identified as the taxon (confidence ≥ 0.8).

2 · One specimen, one taxon: keep the main identification of each specimen.

3 · References from BOLD or NCBI; 500–2,000 bases; same-species records ≥98% identical combined.

4 · Protein check: ≥200 amino acids without a stop codon (genetic code 5).

5 · Align with MAFFT (default) or kc-align (recommended for COI).

6 · Trim with ClipKIT: drop columns that are gaps in ≥90% of sequences.

7 · Tree with IQ-TREE: model chosen automatically, maximum likelihood, no support values.

8 · Figure: midpoint-rooted tree with readable tip labels.

Module 2 does not cluster the local sequences again; that happened in Module 1. Every step writes its own file and its counts to postprocessing.log.

One specimen, one taxon

  • Within each specimen, the identification with the most reads is kept, with all its clusters.
  • Ties are all kept.
  • Every decision is written to extraction_by_specimen_taxon.tsv (column kept_for_tree).
This uses the one-specimen-per-well design: minor identifications in a well are most likely spill-over or errors. They are not deleted; they are listed with kept_for_tree = no, so you can still look at them.

Reference sequences

Where they come from

--bold: a downloaded BOLD public data package (offline, fast).

--download: NCBI GenBank (needs internet).

Records of one species ≥98% identical are combined into one reference, so a species with 300 records does not swamp the tree. Different species are never combined.

Know the caveats

The BOLD file also holds other markers (16S, 28S, ITS, CYTB…). The protein check and kc-align remove most of them.

BOLD records are selected when the taxon name appears in their header, so a few records of other families can slip in. They show up as isolated long branches.

References give your clusters a context of named species. Their names are only as good as the database; BOLD contains misidentified records too. Treat a reference that falls in an odd place with the same suspicion as a local sequence.

The protein check

  • COI codes for a protein. A real COI sequence of ≈658 bases translates into ≈219 amino acids without a stop codon in one reading frame.
  • The check: at least 200 amino acids without a stop, in one of six frames, with the invertebrate mitochondrial code (code 5).
  • It removes many NUMTs (nuclear copies of COI that have decayed), other markers and badly broken reads.

Where to look

translation_lengths.tsv: for every sequence, its best frame, the length and the longest stop-free stretch.

Not every NUMT is caught; young NUMTs still look like COI.

An error-rich single read can fail this check because an insertion shifts the reading frame and creates stop codons. That is fine: consensus sequences of the same specimen usually pass.

Alignment: MAFFT or kc-align

MAFFT · default

General-purpose DNA aligner. Needs no extra file. Fine for any marker.

Can place gaps that break the reading frame.

kc-align · recommended for COI

Aligns codon by codon along a trusted COI guide sequence, so the reading frame stays intact.

Sequences with frameshifts or stops are set aside and listed in *.kcalign_selection.tsv.

Add --kcalign --kcalign-reference GUIDE.fasta.

Choose a guide from the same order or family, from a voucher specimen, full length, no stops (docs/coi_reference.md).

For COI we recommend kc-align. A codon-aware alignment is easier to check by eye: gaps come in threes and amino acids line up. MAFFT stays the default because it works without a guide and for non-coding markers.

Trimming and the draft tree

ClipKIT

Removes alignment columns that are gaps in ≥90% of sequences, mostly ragged ends. A sequence left with no bases is dropped and named in the log.

IQ-TREE

Chooses a substitution model (ModelFinder) and estimates a maximum-likelihood tree. No bootstrap support yet.

Figure

Tree rooted at its midpoint, saved as PDF, PNG and SVG, plus a tips table that tells you what every tip is.

The first tree is a draft for checking the data, not a result to publish. The final tree is estimated after you have reviewed the alignment.

Branch lengths are substitutions per site, not time. Midpoint rooting is only for drawing. For the final tree, remove the sequences you rejected and run IQ-TREE again with support values; the Module 2 guide gives the command.

Trimming, illustrated

ONT "fake introns". An extra base in one read forces a gap into every other sequence. ClipKIT removes that column only when ≥ 90% of sequences have a gap there, so with fewer than 10 sequences, or when two or more reads share the error, it stays and looks like a real insertion. kc-align rejects reads with frameshifts instead. In UGENE, distrust columns filled by one or two single reads.

Ten sequences, so a column with a base in only one of them has 90% gaps and is removed, as are the ragged ends. The extra T shared by two sequences is kept. Repeated ONT errors in runs of one letter, for example TTTTT read as TTTTTT, are exactly the kind of error several reads can share.

Reading this tree

Remove look-alike references

Buteo hemilasius (a buzzard), Olios argelasius (a spider), Aspidolasius: selected only because their names contain "lasius". They form the long outer branches.

L. fuliginosus is clear

The bc1056 clusters sit with the L. fuliginosus reference GBAAZ43772, apart from the other Lasius.

COI has limits

bc1021 groups with L. platythorax and L. niger references mixed together. COI does not separate this pair well; check the specimen's morphology.

Trust tips by their reads

One-read tips on long branches are errors or echoes (reads of a specimen that turned up in another well). Keep the consensus of the real specimen; drop the echoes before the final tree.

This is the review the pipeline leaves to you. Delete the unrelated references and the echo tips, keep one or a few consensus sequences per real specimen, realign if needed and run the final tree with support values. Some L. fuliginosus references also fall in odd places among Pseudolasius; misidentified or mislabelled public records are part of the review too.

Running Module 2 without Module 1

The person who ran Module 1

Packs the analysis tables and the cluster sequences into postprocessing-inputs.tar.gz (docs/sharing_postprocessing.md). No raw reads, no MIDORI.

The collaborator

  1. Installs the taxonomy environment (docs/setup.md).
  2. Gets the BOLD file, or uses --download.
  3. Extracts the archive in the project folder.
  4. Runs Module 2 with the analysis path they were given.
tar --keep-old-files -xzf postprocessing-inputs.tar.gz
This is how a taxonomist can build trees for their group on their own laptop, without the days of classification. Module 2 checks that the sequences match the analysis tables and refuses to run if they do not.

Things to remember

A specimen is a pool + a forward tag

Reads without a trusted tag go to none, which can mix specimens.

Consensus beats single reads

Read counts tell you how much to trust a sequence.

Confidence is not truth

A species missing from MIDORI is named after its closest relative, sometimes confidently.

The tree is a draft

You decide what belongs in the final tree.
